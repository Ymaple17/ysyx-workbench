# 阶段 14b：四槽前端与取指队列

## 学习导航
- **理论目标**：理解四槽 fetch block 中分支、跨 line、fault 和预测 next-PC 如何决定有效前缀。
- **最小实现**：ICache/IFU 产生最多四条连续指令，FetchBuffer/FQ/FTQ 保存四槽 packet，遇到最早 taken control 截断后续槽。
- **当前参考核**：IFU/FQ/FetchBuffer/FTQ 已运行四槽 packet；最新 microbench 的平均 fetch width 为 `3.0922`，但仍有 `FQ Empty=14220`、`FTQ Stale Recover=35`，因此跨行和恢复还未达到最终零错误计数合同。
- **后续扩展**：修复 stale response/recovery 身份后，再评估更宽 cache line、uop cache、多预测分支 fetch block；最小版本每个 block 最多使用一个预测 redirect。
- **验收方式**：四槽同 line、跨 line、每个 lane 分支、redirect 与旧 response、FQ 部分空间、FTQ reuse 定向测试；WIDTH=2 仍可配置。

---

## 1. 最早控制流截断

```text
lane0 lane1 lane2 lane3
  |     |     |     |
find first predicted-taken control
valid lanes after it = 0
next PC = its predicted target
```

若没有 predicted-taken control，next PC 是最后有效指令后的顺序地址。四个 BPU 查询必须使用按 lane 前缀推进后的 speculative history，不能都读取同一个旧 GHR。

## 2. Credit

FQ 接收 count 0..4，并计入同拍 dequeue credit。FetchBuffer 满时只能基于注册且足以容纳整个 head packet 的 credit 做 replacement，避免 ICache live ready 组合环。

## 3. 跨 line

最小实现可以由两个 line response 拼成四槽，但必须保存 request epoch 和 line identity。任一旧 epoch response 只排空；fault 精确附着到对应 lane，不污染更早指令。
