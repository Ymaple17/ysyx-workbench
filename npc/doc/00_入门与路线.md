# 入门与路线

## 学习导航
- **理论目标**：分清发射、写回、提交三个时间点，理解从顺序五级到真乱序双发核的依赖关系和施工顺序。
- **最小实现**：先能按路线找到每章的入口基线、退出能力、源码落点和验收命令；不把最终参考核状态当成自己的学习进度。
- **当前参考核**：阶段 11d 已严格收官，两次 microbench 均为 IPC `1.0117`；本页参数表描述当前源码，各章旧数据只描述本章阶段快照。
- **后续扩展**：MMU/SV32 与多核一致性继续后置到阶段 12；更宽 fetch、完整多 MSHR/更深 LQ、2-way/write-back 和第三 CDB 按新瓶颈数据选择。
- **验收方式**：逐章完成该章清单；参考核总验收为 compile、完整单测、7 项 cpu-tests+difftest，以及 `stage11_final.sh` 的两次严格 microbench IPC `>=1.0`。

## 1. 我们要做成什么

在 **顺序五级** 上分阶段做成 **真乱序双发** 核：

1. **重命名 + ROB 顺序提交** —— 架构态正确、精确异常基础  
2. **保留站乱序发射 + 多 FU / 双整数 ALU** —— 藏 load/div 延迟并支持同拍多发射  
3. **store 提交写 + load 冲突检测** —— 内存序  
4. **双取指 / 双提交 + FQ/FetchBuffer/FTQ + 更强 BPU** —— 把机器宽度真正送到 IPC  

**不是**「在旁边再挂一套不管旧流水」：数据面要从 Refile+arch 前递，逐步换成 PRF+RAT+Busy+ROB(+RS)。

---

## 2. 三个时间点（全书主线）

| 时间点 | 英文 | 含义 | 顺序核里常怎样 | 乱序核必须怎样 |
|--------|------|------|----------------|----------------|
| **发射** | Issue | 指令进入执行部件 | 大致等于进入 EX | RS 选出进入某 FU |
| **写回** | Writeback | 结果写入 PRF，后继可被唤醒 | 常与 WBU 重叠 | **可以乱序**发生 |
| **提交** | Commit | 架构状态对外可见（含 difftest） | 常与写回绑死 | **必须按程序序**（ROB head） |

记一句：

```text
执行可以乱，提交不能乱。
```

difftest、精确异常、软件可见的 CSR/寄存器，认的都是 **提交点**，不是「哪条指令先算完」。

### 2.1 为什么顺序核也能先做 ROB？

即使仍然「最老指令才进 EX」，也可以：

- 用 ROB 记飞行指令的 meta（pc、old/new phys、bp…）  
- 用 PRF 存物理寄存器值  
- 提交时按 head 退休  

这样 **映射与回收** 先调对，再上 RS 时不会和「rename 错」缠在一起。

## 3. 数据相关：顺序前递 vs 重命名

### 3.1 顺序核（ioid）

```text
IFU → IDU → EXU → LSU → WBU
              ↑              │
           Refile 读      Refile 写
              ↑______________│
           前递：比 arch rs === 后面级的 waddr
```

- WAW/WAR 靠「流水里最多几条在飞 + 停顿」压住  
- RAW 靠 EX/LSU/WBU 前递 + load-use stall  

### 3.2 乱序需要多版本

同一架构寄存器 `x1` 可以同时有多个「尚未提交的定义」：

| 冒险 | 没有重命名 | 有 PRF+RAT |
|------|------------|------------|
| WAW | 后写覆盖前写，中间读者可能读错版本 | 每次写分配 **新物理号** |
| WAR | 后写破坏前读还未用完的值 | 读者拿 **旧物理号**，写者写 **新物理号** |
| RAW | 前递/停顿 | **BusyTable**：目的 phys 忙 ⇒ 源未就绪 |

### 3.3 五个部件各管什么

| 部件 | 一句话 |
|------|--------|
| **RAT** | 当前「架构寄存器 → 最新物理寄存器」的推测映射 |
| **arch_rat** | 已提交的映射（冲刷时的安全底） |
| **FreeList / freeBits** | 哪些 phys 空闲，可分配 |
| **PRF** | phys → 值 |
| **BusyTable** | phys 是否「已分配但未写回」 |
| **ROB** | 程序序日志：谁在飞、是否 done、提交时 free 谁、冲刷杀谁 |

典型生命周期：

```text
1. Rename：若 reg_write && rd≠0
     old = RAT[rd]
     new = FreeList.pop
     RAT[rd] = new
     Busy.set(new)
     ROB.enq(..., old, new, ...)
2. 源操作数：psrc = RAT[rs]；等 !Busy[psrc] 或 CDB/旁路
3. 写回：PRF[new]=val；Busy.clr(new)；ROB[idx].done=1
4. 提交（head）：arch_rat[rd]=new；FreeList.push(old)；head++
5. 冲刷：杀 wrong-path；回收它们的 new；RAT 回到正确推测态
     —— 禁止「freeBits 一键变成 32..N_PHYS-1 全空闲」这种硬重置
```

**分配判据必须接译码表，不要自己从指令码猜：**

```scala
do_rename = signals.wbu.reg_write && (waddr =/= 0.U)
// store/branch 的 reg_write=0，即使 inst[11:7]≠0 也不分配
```

## 4. 为什么拆成这么多阶段

| 若一口气做… | 会怎样 |
|-------------|--------|
| 直接 RS+ROB+CDB | 错了分不清 rename / ROB / 唤醒 |
| 先乱序再提交 | difftest 必炸，难回退 |
| 真 freelist 写 + 源仍 arch | 物理写与架构读混用，差分惨不忍睹（已踩坑） |
| StageConnect 只 mask valid | flush 后幽灵指令提交错误 PC |

所以采用 **由易到难、每档可 difftest**：

```text
0   乘除 + 顺序基线（ioid）
1   四件套单测（不接 core）
2a  恒等 pdest + PRF          —— 先让 PRF/提交导出绿
2b  ROB 元数据 + flush 正确  —— 指针/幽灵指令
2c  写侧 freelist            —— 分配/回收/重建 free
2d  源 phys + Busy + pdest 前递
    ↓
3a  写回 ≠ 提交；BPU 表项/committed history@commit；写回门控
3b  RS 壳（仍最老发射）
3c  RS→EX + CDB 口（发射仍最老 ready）
3d  真乱序发射（未 ready enq / 越过最老；单 FU）
    ↓
4a  ROB 补 CSR/state 字段
4b  CSR 架构写 @ commit（+ csr_inflight）
4c  ecall/异常 @ head
4d–4g  ebreak / mret / fencei / 外部中断
    ↓
5a  store@commit
5b  load 冲突 + 去 mem@head
6   前端（FQ 基础已落地）
    ↓
7   调优与参数扫描（先拿 baseline）
    ↓
8a  多 FU 并行（ALU∥DIV∥LSU + 结果仲裁）   ← 超标量第一步
8b  多发射（rename/ROB/RS/FQ 2 宽）
8c  全投机（去 olderCtrl + checkpoint 恢复）
8d  内存乱序（当时为 ROB-backed StoreQueue 消歧；10a 已升级为独立 SQ / StoreBuffer）
    ↓
9a  性能计数器与 baseline
9b  前端 / FQ / BPU 瓶颈分析
9c  参数扫描与 IPC 报告
9d  小步优化与回归方法
    ↓
10a 独立 SQ + store buffer
10b 访存层次（blocking DCache；MLP 非阻塞为扩展）
10c 宽提交 + 多 CDB
10d 宽取指与前端带宽
10e 高级分支预测（tagged override / 间接跳转；10j 再升级成多历史 TAGE/ITAGE）
10f 真正 2-wide commit / retire
10g 扩大乱序窗口：ROB / RS / PRF / FQ
10h 重新启用宽取指
10i 非阻塞 DCache / MSHR
10j 完整 TAGE / ITAGE
10k 放宽双提交类型（load / control-flow / store）
10l Load Queue / replay / 内存违例恢复
10m 持续双取指 / FetchBuffer / FTQ
11a 依赖链与执行吞吐（同拍 wake/select + 弹性 refill）
11b 访存吞吐与 DCache 重构（burst / store merge / MSHR）
11c 持续前端与有效宽度（branch+lane1 / targeted BPU）
11d IPC 1.0 验收与回归（周期账本 + 严格收口）
12a MMU / SV32 虚拟内存（后置可选大项）
12b 多核与缓存一致性（科普 / 可选）
```

**铁律：**

1. **2d 自测不过 → 禁止 3b**  
2. **3a 自测不过 → 禁止 3c**；**3c 结构不通 → 禁止 3d**  
3. **3d 自测不过 → 禁止把「真乱序」当完成**；再进 4  
4. **4b 不过 → 不做 4c**（先稳住 CSR 写点）  
5. freelist flush **禁止**硬重置成 `32..N_PHYS-1` 全空闲
6. **8a 不过 → 不做 8b**；**8b 不过 → 不做 8c**；**8c 不过 → 不做 8d**（每级依赖上一级结构）  
7. 计划与实现冲突 → **先改文档**

### 5.1 目录约定（强制）

| 目录 | 放什么 |
|------|--------|
| `core/` | **仅**流水级 |
| `unit/` | 功能部件 + OoO 四件套/RS |
| `common/` | 常量、OoOParams |

旧笔记若写 `core/prf.scala`，一律读作 **`unit/prf.scala`**。

### 5.2 仿真提交口

| 用途 | 信号 |
|------|------|
| slot0 是否提交 | `io_commit_valid` |
| slot0 提交 PC / MMIO 地址 / load 标志 | `io_commit_pc` / `io_commit_mem_addr` / `io_commit_is_load` |
| slot1 是否提交 | `io_commit_valid1` |

顺序核 ioid 曾抠 `wbu_io_in_valid` 层次；oood **不要**再走那条路。

### 5.3 关键参数

下表是**当前参考核水位**，不是每个早期阶段一开始就必须全部实现。比如阶段 1 只需要四件套相关参数；FQ、issue width、SQ、DCache 是后续章节逐步打开的。

| 参数 | 当前值 | 含义 |
|------|------|------|
| ROB_SIZE | 32 | 阶段 10g 保留点；在飞指令上限（也限制写目的数） |
| N_PHYS | 64 | 32 架构初值槽 + ROB_SIZE 可重命名槽 |
| PHYS_W | 6 | |
| RS_SIZE | 8 | 阶段 3b 起 |
| FQ_SIZE | 8 | FetchQueue 深度；阶段 6 最小可从 4 起，阶段 9 推荐点保留 8 |
| FETCH_WIDTH / FETCH_BUFFER_SIZE | 2 / 2 | 阶段 10m 建立双槽 fetch block；11c 放行安全 branch+lane1 |
| FTQ_SIZE / FTQ_GEN_W | 16 / 8 | 阶段 10m：预测元数据、RAS snapshot 与槽复用身份 |
| WIDE_FETCH_ENABLE | true | 阶段 10m 持续双槽供给 |
| WIDE_FETCH_MIN_SPACE | 6 | FetchBuffer/FTQ 和更强后端接入后的保留 credit；不能套用 10h 旧核的退化结论 |
| ISSUE_WIDTH / DISPATCH_WIDTH | 2 | 2 宽 rename/dispatch；该参数不限制同拍 FU fire 数，RS 有 ALU0/ALU1/LSU/DIV 分布式 issue 口 |
| COMMIT_WIDTH | 2 | 10k 已允许安全的普通 load、控制流与 cacheable store 进入 lane1；特殊/异常/MMIO 仍独占 |
| CDB_NUM | 2 | 双 CDB；4→2 arbiter 按 ROB age 选最老两项；11a 的无目的控制流从独立 sideband 完成 |
| CP_DEPTH | 4 | 阶段 8c 分支 checkpoint 深度 |
| SQ_SIZE | ROB_SIZE | 阶段 10a 的 ROB-indexed 独立 StoreQueue |
| STORE_BUFFER_SIZE | 16 | 阶段 11b：同 word 合并、最多 8-beat 连续写 burst、每拍 drain 精确更新 cache |
| DCACHE_SET / DCACHE_BLOCK_SIZE | 64 / 32B | 阶段 11b：2KiB direct-mapped、同拍 hit、active MSHR + secondary slot/same-line merge |
| LSU_MLP_ENABLE / LQ_SIZE | true / 4 | LQ tagged replay；11b 支持新请求同拍 cache response，最终 LQ full 仅 `325` cycles |
| LQ_SPECULATE_UNKNOWN_STORES | false | 保留点对未知 older store 采用保守等待；违例检测硬件保留供实验 |
| TAGE_TABLE_SIZE / HISTORY | 256 / 2,5,10 | 阶段 10j 保留点；三张方向 tagged table |
| ITAGE_TABLE_SIZE / HISTORY | 128 / 4,10 | 阶段 10j 保留点；两张间接目标 tagged table，PC-only 表作 alternate |

复位后的 freelist：物理号 **0..31** 视为「初始绑定到 x0..x31」**不空闲**；当前 `N_PHYS=64`，因此 **32..63** 空闲可分配。phys0 永不分配、永不释放；若改变参数，这个范围应写成 `32..N_PHYS-1`，不能硬编码上界。
