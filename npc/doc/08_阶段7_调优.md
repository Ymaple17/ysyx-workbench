| 项 | **现状** | **本阶段常见动作** |

## 1. 调优在做什么

```text
正确性（0–6 阶段）→ 早期基线调优（本阶段 7）→ 结构升级（阶段 8）→ 性能画像与系统调优（阶段 9）
```

每一拍 CPU 可能卡在：

| 瓶颈类型 | 表象 |
|----------|------|
| 前端 | I$ miss、FQ 空、误预测气泡 |
| 命名/调度 | freelist 空、ROB 满、RS 满、olderCtrl/mem@head |
| 执行 | DIV 串行占 d_reg、ALU 端口不够、CDB 拥堵 |
| 访存 | D$ miss、store 提交排队、load 等 store |
| 提交 | 单宽 commit、store 写总线阻塞 head |

调优 = **测量 → 假说 → 只改一处 → 再测量**。

## 2. 指标定义（先统一）

| 指标 | 定义 |
|------|------|
| 周期数 | 仿真 `main_time/2` 或自建 cycle 计数 |
| 提交指令数 | `commit_fire` 次数（不含气泡） |
| **IPC** | 提交指令数 / 周期数 |
| 误预测率 | mispred / 可预测分支数 |
| ROB 满停顿 | rename 因 `rob.full` stall 的周期 |
| FL 空停顿 | `fl_empty` stall 周期 |
| RS 满停顿 | `rs.full` stall 周期 |
| FQ 空/满 | 见阶段 6 |
| CDB 冲突 | 多 FU 完成但单端口仲裁失败次数 |
| DIV 占用 | div_busy 周期 |

仓库已有 `PerfMonitor` / `EVENT_*`、统计打印：优先复用，缺的再加 `dontTouch` 计数器。

## 3. 固定测试集（避免「换题刷分」）

建议三档：

1. **功能回归**：cpu-tests 全过（正确性门禁，不单看 IPC）  
2. **小微基准**：add、bubble-sort、qsort、string、load-store  
3. **较长负载**（若有）：coremark / 自建矩阵 / 递归  

每次调参 **同一组 bin、同一编译选项**。

## 4. 参数扫描表

| 参数 | 位置 | 初值 | 扫描建议 | 主要影响 |
|------|------|------|----------|----------|
| ROB_SIZE | OoOParams | 16 | 8/16/32 | 窗口、N_PHYS |
| N_PHYS | 32+ROB | 48 | 随 ROB 或更大 | freelist 压力 |
| RS_SIZE | OoOParams | 8 | 4/8/16 | 等待缓冲 |
| FQ_SIZE | OoOParams | 4 | 2/4/8 | 前端解耦 |
| CDB 端口 | core | 1 | 1/2 | 写回带宽 |
| BHT_SIZE | BPU_Config | 已有 | ×2/×4 | 误预测 |
| RAS_SIZE | BPU_Config | 已有 | 8/16/32 | call-ret |
| ICache set/way | core 例化 | 64×4 | 改关联度 | 前端 miss |

**注意**：`N_PHYS` 与 freelist 初值、rename 位宽、PRF 深度必须一起改；ROB 非 2 次幂时指针加法要小心（当前 require 16）。

---

## 5. 推荐扫描流程

```text
1. 记录 baseline（当前参数）整表指标
2. 只改 ROB 16→32，N_PHYS 同步，测表
3. 恢复，只改 RS_SIZE
4. 恢复，只改 FQ_SIZE
5. 看「边际收益」：IPC 提升 < 2% 且面积/仿真变慢 → 不取
6. 组合最优 2–3 个参数做一次确认回归
```

禁止一次改五个参数导致无法归因。

## 6. 结构级优化方向（有数据再动）

| 假说 | 若数据支持 | 动作 |
|------|------------|------|
| 误预测气泡大 | 误预测率高、错误路径提交少 | 阶段6 调 BPU |
| DIV 挡一切 | div 多且 RS 不并行 | 确认 3c DIV 独立 FU |
| CDB 拥堵 | 仲裁失败多 | 双 CDB 或优先级 |
| store 堵 commit | head 常为 store 等待总线 | 写缓冲、与阶段5 协同 |
| freelist 空多 | FL 空停顿高 | 加大 N_PHYS / 更快回收 |
| ROB 满多 | 长延迟多 | 加大 ROB 或减延迟 |

## 9. 踩坑

| 现象 | 原因 | 处理 |
|------|------|------|
| IPC 升但测例挂 | 破正确性 | 任何调参后跑功能回归 |
| 改 ROB 仿真炸 | N_PHYS/指针未同步 | 参数打包改 |
| 数字不可复现 | 未固定 bin/种子 | 锁测试集 |
| 只看 dummy IPC | 太短无意义 | 用长测例 |
| 优化了 EX 更新 BPU | 正确性回退 | 保持 commit 更新 |

## 11. 附录：IPC 与「看起来变快」

```text
IPC 高 ≠ 墙钟一定快
仿真器本身变慢（ROB 大）时，看 cycles 比看仿真秒数有意义
```

对 npc 仿真：优先 **cycles 与 commit 数**，墙钟仅作辅助。

## 12. 附录：最小计数器插入点

## 14. 仓库实测

- 基线 16/8/4：PASS，cycles 1584103，IPC 0.3298，ROB Full 506，RS Full 252556，FQ Full 459052。
- 32/8/4：PASS，cycles 1592008，IPC 0.3283，ROB Full 12069，RS Full 377280，FQ Full 522131。
- 16/16/4：PASS，结果和 32/8/4 基本一致。
- 16/8/8：HANG，qsort 卡死。
- 32/16/4：HANG，组合后卡死。

结论：最终保持 ROB=16, RS=8, FQ=4。放大 ROB/RS 没有带来可接受的周期收益，FQ=8 会破坏稳定性。
