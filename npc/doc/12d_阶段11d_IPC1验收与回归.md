## 学习导航
- **理论目标**：掌握性能优化的实验纪律：固定 workload、单变量 A/B、周期归因、正确性门槛和重复性；理解 IPC 达标不能替代 difftest。
- **最小实现**：把 11a-11c 的保留改动按依赖顺序合并，补齐阶段 11 专用计数器/解析脚本，完成编译、单测、cpu-tests+difftest 与至少两次严格 microbench。
- **当前参考核**：Stage11d 历史收官仍由 `stage11_final.sh` 证明（两次 IPC `1.0117`）；当前源码已完成 Stage12f 最终回归，两次 IPC 均为 `1.3736`，Stage11 数据只作为下一章的固定基线。
- **后续扩展**：阶段 12 继续解决 CDB/FQ/branch/load 迁移瓶颈并收口 IPC 1.3；系统能力后置到阶段 13。
- **验收方式**：功能门、性能门、重复性门和文档门全部通过；最终脚本要求一次 full regression 加同一二进制复跑，两次 IPC 均 `>=1.0`、差值 `<=0.005`，且无 HANG/ABORT/difftest mismatch。

## 3. 阶段 11 周期账本

最终报告至少包含下面四列：

| 类别 | 10m baseline | 11 final | delta / 解释 |
|------|-------------:|---------:|--------------|
| cycles / commits / IPC | `818892 / 522548 / 0.6381` | `516339 / 522374 / 1.0117` | `-302553` cycles，跨过 1.0 |
| head wait | `363162` | `120998` | `-242164`，依赖/访存完成更连续 |
| wait store commit | `43219` | `3287` | burst drain 与合并 |
| slot1 commit / util | `177024 / 51.23%` | `195616 / 59.87%` | 有效供给和后端服务率共同改善 |
| DCache replay / SB full / LQ full | `54040 / 41278 / 7761` | `964 / 1348 / 325` | 11b 服务率主收益 |
| fetch avg width / slot1 killed / flush | `1.3858 / 55860 / 18827` | `1.5436 / 49265 / 17450` | 11c 有效宽度 |
| DCache hit rate | `71.28%` | `97.29%` | 32B line + 2KiB capacity |
| CDB conflicts | `6904` | `7279` | 主墙移除后写回压力略升 |

计数器分类应尽量互斥且能加总。例如 no-slot0-commit 周期应继续满足：

```text
no_commit = head_wait + wait_store_commit + empty_or_recovery_or_other
```

slot1 也应满足：

```text
slot0_commit = slot1_commit + slot1_not_ready + slot1_blocked
```

若等式不成立，先修统计定义，不能用重叠计数直接估收益。

## 4. A/B 保留规则

每个候选改动只允许三种结论：

| 结论 | 条件 | 动作 |
|------|------|------|
| 保留 | 正确性全绿，目标瓶颈下降，总周期改善 | 合入下一基线 |
| 拒绝 | 正确但 IPC/总周期退化，或错误路径/压力明显恶化 | 回退该候选，记录负结果 |
| 待解释 | IPC 波动小，局部指标相互抵消 | 补计数/重复实验，不立即叠下一个改动 |

不要同时打开 burst、2-way、4-MSHR、LQ8 和 loop predictor 后只报告最终 IPC。参考核没有这样做：2-way、LQ8、完整多 MSHR、loop predictor 和 4-fetch 都没有冒充已实现能力；它们缺乏当前计数器证据，或受单 read-owner 总线限制。

## 5. 推荐集成顺序

```text
baseline 10m
  -> 11a counters only
  -> 11a same-cycle RS wake/select
  -> 11a LSU elastic refill
  -> 11b one-hit-per-cycle
  -> 11b burst transport
  -> 11b cache geometry A/B
  -> 11b store-hit update + write combining
  -> 11b secondary miss slot + same-line merge
  -> 11c branch+lane1 dispatch
  -> 11c bimodal/TAGE tournament
  -> reject wider fetch/multi-MSHR/LQ growth unless counters require
  -> 11d two-run final closure
```

每个箭头都是一个可单独回归的保留点。这里允许实现过程中发现某项收益不足而拒绝它，但不允许把本阶段最小实现中的正确性缺口改名塞进阶段 12。

## 6. 当前保留与拒绝记录

| 保留点 | IPC | 关键结论 |
|--------|----:|----------|
| 10m baseline | `0.6381` | 固定比较口径 |
| selective LSU flush + 弹性路径 | `0.8498` | 消除错误的全 LSU flush/重放损失 |
| store write burst + branch/lane1 | `0.9195` | StoreBuffer 压力基本清除，前端有效宽度上升 |
| bimodal/TAGE tournament | `0.9336` | 局部分支补充 history predictor |
| control direct completion | `0.9434` | 无目的控制流不再争数据 CDB |
| secondary miss + merge | `0.9459` | 两请求身份和同线复用有效，但单总线限制收益 |
| 32B line + precise drain update | `0.9585` | 命中率显著提高并修复 refill/store 竞态 |
| same-cycle DCache hit/LQ response | `1.0117` | 去掉命中路径固定一拍，达到本阶段目标 |

两个失败实验尤其需要保留：第一次直接上 32B line 因 StoreBuffer drain/refill 窗口在 Dinic difftest mismatch；补精确 drain update 后才可保留。第一次把 flow queue 的 `enq.valid` 写成依赖 `cpuArFire` 会形成 Decoupled 组合环；最终改为只依赖 request valid + tag hit。

## 7. 达不到 1.0 时怎么继续

若 11a-11c 已按定义完成但 IPC 仍低于 1.0，按剩余周期占比选择下一刀：

| 剩余主因 | 下一步 |
|----------|--------|
| ALU dependency head wait | 查 bypass 覆盖、ALU pipeline latency、issue select critical path |
| load head wait / DCache busy | 增 MSHR/端口、优化 miss merge、检查总线并行度 |
| store commit wait | 扩大合并窗口、write-back cache、提高写通道并行度 |
| FQ empty / useful supply < 1 | 更宽 fetch block、banked ICache、多分支预测 |
| branch flush dominant | 按 PC/类型做 top-N miss profile，再设计 predictor |
| CDB conflict 新增 | 先看 result buffering/仲裁公平，再评估第三 CDB |
| ROB/RS full 新增 | 说明瓶颈已迁移，此时才重新扫描窗口 |

阶段 11 的目标是完整解决“从 0.6 到 1.0”这条主线，所以这些是本阶段内的诊断分支，不自动顺延为阶段 12。
