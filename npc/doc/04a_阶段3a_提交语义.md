# 阶段 3a：提交语义（写回 ≠ 提交）

## 学习导航
- **理论目标**：本章先理解：语义上拆开 **写回** 与 **提交**；写回按动态指令身份门控；BPU 的架构训练状态在 **提交时**更新。
- **最小实现**：结果在 writeback 写 PRF/清 Busy，只有 ROB head commit 才更新架构视图与 BPU；所有写回先过动态指令身份门控。
- **当前参考核**：阶段 10m 已多 FU、2 CDB、2-wide commit，但仍严格保持本章的“写回可乱、提交有序”边界。
- **后续扩展**：3b 先接 RS 壳并保持最老发射，3c 再让 RS 驱动 EX/CDB。
- **验收方式**：涉及 RTL 时至少跑 `./mill -i mychisel.compile`、相关单测和 cpu-tests；涉及性能时再跑 `microbench mainargs=test` 并记录 before/after。

**目标**：语义上拆开 **写回** 与 **提交**；写回按动态指令身份门控；BPU 的架构训练状态在 **提交时**更新。

## 1. 原理

### 1.1 两个事件

| 事件 | 做什么 | 顺序 | 乱序后 |
|------|--------|------|--------|
| 写回 WB | PRF 写值；Busy 清；ROB.done=1 | 常是最老 | **任意完成的指令** |
| 提交 COM | free(old)；arch_rat；arch_rf；对外 commit_*；BPU update | 常与 WB 绑 | **仅 ROB head 且 done** |

若乱序后仍 `wb_fire ⇒ commit_fire`：

```text
后发先完成的 addi 会先「提交」
先发的 div 后完成 → 架构序错，difftest 必炸
```

### 1.2 写回门控

冲刷后 ROB 项 `valid=0`，但其 FU 可能仍会完成：

```text
can_wb = rob(idx).valid && !rob(idx).done && rob(idx).identity == wb.identity
仅 can_wb 时写 PRF / clr busy / 标 done
```

`idx` 只是循环队列槽号，flush/commit 后会复用；身份至少要核对该动态指令随执行链携带的 `pc/new_phys/arch_rd`（或显式 generation tag）。否则旧 FU 响应可能命中新占用同一槽的指令，把结果写入 **已回收再分配** 的 phys，造成静默数据损坏。PRF、BusyTable、ROB done 和 RS free 都应由同一个身份验收结果门控。

### 1.3 BPU 训练为何必须以 commit 为准

| 在 EX 更新 | 后果 |
|------------|------|
| ghr 按执行序翻 | 与程序序历史不一致 |
| RAS push/pop 按执行序 | ret 目标错乱 |

正确：

```text
EX/BRANCH FU：算 correct_pc、is_ch、mispred → 冲刷前端
COMMIT：若 head 是 branch/call/ret → bpu_update_*
```

`bp_index` 等必须在 **enq 时存进 ROB**，提交时用 ROB 里的，而不是 EX 当前指令的。

这是本章的最小可靠实现。当前阶段 10m 为提高连续预测能力，会在 fetch 时投机推进 GHR/RAS，并把旧历史保存在 FTQ；错误路径通过 FTQ 恢复。方向表、目标表和 committed history 的训练仍按程序序在 commit 更新，不能把“fetch 时投机历史”误写成“EX 时训练预测器”。

## 2. ROB 已有能力（对照源码）

`unit/rob.scala`：

```scala
commit_valid = head.valid && (head.done || wb_is_head)
// wb_is_head = wb_fire && wb_idx===head && head.valid
```

`wb` 口：`wb_idx` 可选任意项；`wb_actual_taken` 写入 `actual_taken`。

你要在 **core** 改的是驱动方式，不是推倒 ROB。

---

## 3. core 目标接线

### 3.1 写回

```scala
wb_fire = wbu.valid && !flush
wb_idx  = wbu.rob_idx          // 不要写死 head
can_wb  = wb_fire && entries(wb_idx).valid && !entries(wb_idx).done && identity_match

prf.wen  := can_wb && reg_write && pdest=/=0
busy.clr := 同上
rob.wb_fire := can_wb
rob.wb_idx  := wb_idx
rob.wb_val  := wdata
rob.wb_actual_taken := wbu.br_taken
```

### 3.2 提交

```scala
rob.commit_fire := rob.commit_valid

cm = rob.commit_bits
cm_do_ren = commit_fire && cm.reg_write && cm.arch_rd=/=0 && cm.new_phys=/=0

rename.commit_* := 来自 cm（old/new/arch_rd）
arch_rf(cm.arch_rd) := Mux(同拍wb head, wbu.wdata, cm.dest_val)
```

**同拍 head 写回**：`entries.dest_val` 是寄存器，当拍组合读仍是旧值，arch_rf 必须优先用 WBU 数据。

### 3.3 导出 difftest

```scala
io.commit_valid := rob.commit_fire
io.commit_pc    := cm.pc
io.commit_mem_addr := Mux(同拍wb, wbu.alu_result, cm.mem_addr)
io.commit_is_load  := cm.reg_write_sel === MEM_SEL
```

### 3.4 流水携带 br_taken

- EXU：`br_taken := (pc_src =/= PC_PLUS4)`  
- 经 LSU Bundle 到 WBU  
- ROB enq：存 `jump, bp_*, inst`  
- wb：写 `actual_taken`  

### 3.5 BPU 搬家

```scala
// 删除：ifu.bpu_update_valid := is_jump  // EX 时

// 改为：
cm_is_jump = commit_fire && (cm.jump =/= JUMP_NONE)
ifu.bpu_update_valid := cm_is_jump
ifu.bpu_update_taken := cm.actual_taken
ifu.bpu_update_pc    := cm.pc
ifu.bpu_update_index := cm.bp_index
// is_branch / call / ret 用 cm.jump 与 cm.inst 的 rd/rs1 判
```

**mispred 冲刷仍在 EX**，不要搬到 commit（那会太晚）。

## 4. flush 重建与 commit

3a 后 `cm_fire` 可能独立于「任意 wb」。  
rebuild 的「同拍 commit」基线应跟 **commit_fire**，不是任意 `wb_fire`。

---

## 5. 顺序核行为应保持

在仍顺序发射时：

- WBU 指令就是 head  
- `can_wb` 恒真（valid 且未 done）  
- `commit_valid` 因 `wb_is_head` 同拍为真  
- 对外仍每指令一拍 commit，dummy/add 应继续绿  

若 3a 后回归挂了，优先查：arch_rf 同拍值、commit_pc 是否改绑错、BPU 更新丢失导致收敛变慢（一般不应功能错）。

---

## 6. 踩坑

| 坑 | 处理 |
|----|------|
| commit 用 cm.dest_val 但同拍 wb | Mux wbu.wdata |
| BPU 仍 EX 更新 | 关掉 EX 路径 |
| enq 未存 bp_index/jump | 提交时无信息 |
| wb_idx 仍写 head | 乱序时标错 done |
| 杀项 can_wb 为真 | 查 valid 是否 flush 清了 |

## 附录 B：call/ret 在 commit 的识别

```scala
rd  = inst(11,7)
rs1 = inst(19,15)
is_call = is_jump && rd===1 && (jump===JAL || (jump===JALR && rs1=/=1))
is_ret  = is_jump && jump===JALR && rs1===1
```

与 EX 时代码保持一致，只是 `inst/jump` 来自 `commit_bits`。
