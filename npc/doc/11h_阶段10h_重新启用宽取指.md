# 阶段 10h：重新启用宽取指

## 学习导航
- **理论目标**：理解宽取指只有在提交宽度、乱序窗口和预测质量足够时才会变成有效 IPC；否则它会制造 wrong-path 压力。
- **最小实现**：在 10f/10g 后重新打开 `WIDE_FETCH_ENABLE=true`，扫描 `WIDE_FETCH_MIN_SPACE`，用 slot1 利用率、FQ 压力和 IPC 判断是否保留。
- **当前参考核**：10h 的保守 wide-fetch 是历史中间点；10m 在 FetchBuffer/FTQ 和更强后端上重新保留 `WIDE_FETCH_MIN_SPACE=6`，最终平均 fetch width `1.3858`。本章的 `space=6` 退化结论只适用于当时缺少解耦和后端吞吐的旧核。
- **后续扩展**：跨 line 已命中 slot1、FTQ、前端 redirect 恢复和后端吞吐已在 10m 完成；当前可继续做 fetch-block cache、多 bank ICache、decode queue 和 loop buffer。
- **验收方式**：比较 no-wide 与 wide 的 regression；必须记录 `fetch_slot1_util_pct`、`FQ_ENQ2`、`FQ_FULL`、`BP_FLUSH`、IPC。

---

## 1. 为什么不能只改一个开关

10d 已经验证：在当时 1-wide commit/ROB16 时打开 slot1 会退化。10h 必须建立在：

```text
10f 真正 2-wide commit
10g 更大的乱序窗口
10e 最小高级 BPU
```

之后再重新尝试。否则看见的不是前端带宽收益，而是错误路径和 backpressure。

---

## 2. 实验矩阵与结论

| 配置 | 参数 | IPC | 前端现象 | 决策 |
|------|------|-----|----------|------|
| no-wide | `WIDE_FETCH_ENABLE=false` | 0.4330 | `fetch_slot1_util=0.00%`，`FQFull=203931` | baseline |
| wide-space-full | `WIDE_FETCH_ENABLE=true`，`WIDE_FETCH_MIN_SPACE=FQ_SIZE` | 0.4343 | `fetch_slot1_util=5.44%`，`FQEnq2=49665`，`FQFull=214835` | **保留** |
| wide-space-6 | `WIDE_FETCH_ENABLE=true`，`WIDE_FETCH_MIN_SPACE=6` | 0.3902 | `fetch_slot1_util=23.87%`，但 `FQFull=423067`、`HeadWait=617868` | 拒绝 |

space=6 已经明显退化，因此 10h 本轮不继续跑更激进的 space=4 / space=2。它们只会更频繁制造 slot1 fetch，而 10h 后端和预测质量还消化不了。

完整 CSV：[`stage10h_scan_results.csv`](stage10h_scan_results.csv)。

## 3. 保留点源码

`common/ooo_params.scala`：

```scala
val FETCH_WIDTH = 2
val WIDE_FETCH_ENABLE = true
val WIDE_FETCH_MIN_SPACE = FQ_SIZE
```

`core/core.scala` 仍然让 IFU 本地接收一个分布式门控信号：

```scala
ifu.io.slot1_enable :=
  if (OoOParams.WIDE_FETCH_ENABLE)
    fq.io.space >= OoOParams.WIDE_FETCH_MIN_SPACE.U
  else
    false.B
```

这个保留点不是“每拍都取两条”，而是“FQ 基本空且 slot0 不预测 taken 时才取第二条”。它的收益很小，但说明 10f/10g 之后宽取指不再必然拖慢核。

---

## 4. 怎么读这组结果

wide-space-full 的 IPC 小涨来自更高的有效前端供给：`Fetch Slot1 Valid=49665`，`FQ Enq2=49665`，commit slot1 利用率从 no-wide 的 `5.99%` 到 `6.03%`，略有提升。

wide-space-6 的反例更重要：slot1 fetch 利用率提高到 `23.87%`，但 IPC 掉到 `0.3902`。这说明“取到第二条”不等于“第二条有用”。在 10h 阶段核里，更多 slot1 会放大 FQ backpressure、head-not-ready 和 wrong-path 压力，最后反而让后端退休更少。

所以 10h 的工程结论是：

```text
可以保守重新启用 slot1；
不能激进追求持续 2-wide fetch；
10i 随后补 1-entry MSHR/hit-under-miss 骨架，但当时默认关闭激进 LSU MLP，因为实测 `LSU_MLP_ENABLE=true` 只有 2 次 hit-under-miss 且 IPC 退化到 `0.3837`。10j 完成多历史 TAGE/ITAGE，10l 又补完整 LQ/replay 并安全重开 MLP；这些都是本章快照之后的演进。
```
