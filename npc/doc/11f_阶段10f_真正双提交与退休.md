# 阶段 10f：真正 2-wide commit / retire

## 学习导航
- **理论目标**：理解写回可以乱序多路，但提交必须从 ROB head 开始按程序序退休；真正 2-wide commit 是 IPC 破 1 的硬前置。
- **最小实现**：保持访存、控制流、CSR/异常等有副作用指令单独提交，先让连续两个已完成的普通 ALU/算术类指令一拍退休；同时拓宽 rename commit、arch view、C++ difftest 提交事件和性能计数。
- **当前参考核**：已完成 10f 最小参考核，`COMMIT_WIDTH=2`；microbench(test) 中出现真实双提交，`commit2_cycles=28744`，IPC `0.4302`。
- **后续扩展**：放宽 load/branch slot1、store slot1 提交、双 BPU update、更大 ROB/RS/PRF、重新开启宽取指。
- **验收方式**：先跑双提交单测，再跑 `mychisel.compile`、cpu-tests + difftest、`microbench(test)`；性能上重点看 commit2 计数、Head Not Ready、IPC。

---

## 1. 为什么 10f 必须补上

现在的核已经有：

```text
2-wide rename/dispatch
多 FU
2 CDB 写回
2-slot fetch 基础设施
```

但提交口仍然是：

```text
io_commit_valid
io_commit_pc
io_commit_mem_addr
io_commit_is_load
```

也就是 C++ 每拍只检查一条指令。这样即使后端同拍完成两条，ROB 也只能每拍退休一条，理论 IPC 上限被卡在 1 以下。

真正 2-wide commit 的语义是：

```text
从 ROB head 开始，若 head 已完成，则提交 slot0；
若 head+1 也有效、已完成、且不是需要独占提交的指令，则同拍提交 slot1；
两个提交事件严格按程序序对外可见。
```

---

## 2. 最小实现边界

本章先不追求所有指令都能 slot1 retire。为了可调试，先保守：

| 类型 | slot0 | slot1 |
|------|-------|-------|
| 普通 ALU/算术/逻辑 | 可以 | 可以 |
| 普通 load | 可以 | 当前参考核先独占提交拍，后续再放宽 |
| 普通 branch/jal/jalr | 可以 | 当前参考核先独占提交拍，避免同拍双 BPU update/RAS/GHR 顺序问题 |
| store | 可以 | 当前参考核先独占提交拍，StoreBuffer enqueue 仍保持单路 |
| CSR / ecall / mret / fence.i / ebreak / exception / MMIO | 独占提交拍 | 禁止 |

最小参考核可以先实现：

```text
slot0_valid = old head commit_valid
slot1_valid = next entry valid && done && slot0_valid && !slot0_exclusive && !slot1_exclusive
```

当前源码里的 `cm_exclusive/cm1_exclusive` 比目标表更保守：只要涉及 `mem_valid`、CSR 写、`fence.i`、`mret`、`ebreak`、异常状态或控制流跳转，就挡住 slot1。这样做的好处是 difftest 和副作用顺序最容易验稳；坏处是 `commit_slot1_util_pct` 还不高，10f 只是先打开退休宽度上限。

后续再逐步放宽 load、store、branch 双更新和更多特殊组合。

## 3. RTL 需要拓宽的接口

### 3.1 ROB

ROB 要从单提交输出变成 batch。当前参考核为了少改调用面，没有直接改成 `Vec(2, ...)`，而是在原 slot0 接口旁边增加 slot1：

```scala
commit_valid
commit_idx
commit_bits
commit_fire

commit1_valid
commit1_idx
commit1_bits
commit1_fire
```

提交指针更新：

```text
nCommit = PopCount(commit_fire)
head := head + nCommit
count := count - nCommit + enq_count - flush_kill_count
```

flush 与双提交同拍时，仍然要以“提交后的 head”作为保留区间基准，这点和 2b/3a 的单提交规则一样。

### 3.2 Rename / FreeList / arch_rat

两条写寄存器指令同拍提交时：

```text
arch_rat[rd0] = new0
free(old0)
arch_rat[rd1] = new1
free(old1)
```

如果两条提交都写同一个架构寄存器，slot1 更新应覆盖 slot0 的 arch_rat；两个 old_phys 都要按各自 ROB entry 回收。

### 3.3 arch_rf / difftest view

C++ difftest 要么每拍 step 两次，要么 RTL 导出两个 commit event。当前参考核拓宽顶层为：

```text
io_commit_valid  / io_commit_pc  / ...
io_commit_valid1 / io_commit_pc1 / ...
```

为了兼容旧脚本，可以保留 `io_commit_valid` 作为 slot0 alias。

### 3.4 StoreQueue / StoreBuffer

完整设计里 StoreQueue commit 清理也要支持两路：

```text
sq.commit0
sq.commit1
```

当前参考核先让 store 独占提交，所以 slot1 不会是 store，StoreBuffer enqueue 仍保持单路；后续再做 store slot1 commit。

### 3.5 BPU update

最保守做法：含控制流更新时独占提交。这样 BPU update 仍保持单口。

更激进做法：BPU 支持两路 commit update，但 RAS/GHR 更新顺序要严格 slot0 -> slot1。

## 4. C++ difftest 改造

旧模型是一拍最多一次：

```cpp
if (top->io_commit_valid) {
  difftest_step(top->io_commit_pc);
}
```

10f 应改成：

```cpp
for lane in 0..1:
  if (commit_valid[lane]) {
    difftest_step(commit_pc[lane]);
    check arch regs after this retired instruction
  }
```

当前 C++ 路径按 lane0 -> lane1 顺序推进 NEMU。因为 DUT 的 arch view 是同拍结束后的最终状态，寄存器比较仍放在下一次提交开始前统一检查；lane1 只允许非 MMIO、非访存副作用的普通指令，避免要求 C++ 观察 slot0 和 slot1 之间的中间态。

## 5. 性能计数器

新增：

| 计数器 | 含义 |
|--------|------|
| `EVENT_COMMIT_SLOT0` | slot0 提交次数 |
| `EVENT_COMMIT_SLOT1` | slot1 提交次数 |
| `EVENT_COMMIT2` | 同拍提交两条次数 |
| `EVENT_COMMIT_SLOT1_BLOCK` | slot1 有机会但被保守条件、未完成或 flush/redirect 等原因挡住 |

验收时不要只看 IPC，要看 `Commit2 Cycles / Commit Slot0` 是否真的上来。
