# 阶段 15e：六宽分布式后端与 IPC 3.0

## 学习导航
- **理论目标**：理解从四宽到六宽时，全连接 PRF/RS/CDB 的面积与时序为什么超线性增长，以及 cluster/local-credit 如何把控制靠近资源。
- **最小实现**：仅当后续规模测试证明四宽退休、PRF/CDB/RS credit 已成为主瓶颈时，才参数化 `CORE_WIDTH=6`，使用两个三宽执行 cluster、本地 issue/operand/completion 和有界跨 cluster 转发。
- **当前参考核**：Stage15 工作参考冻结于四宽 IPC `2.3005`；六宽没有接入，也不是本阶段完成条件。当前每拍最多一条 control，但 Store 地址已经通过独立 Sidecar 与 Store data readiness 解耦。
- **后续扩展**：第二 BRU、双 Store address、三 Load bank、更宽 Trace 和更多 cluster；只在对应 admission counter 成为主因时增加。
- **验收方式**：WIDTH=4 等价回归、WIDTH=6 rename/ROB/commit 随机模型、cluster credit、跨 cluster wakeup、异常/redirect、lane4/5 实际提交，以及全核 cycles 正收益。

## 1. 进入条件

满足以下条件才开始六宽：

```text
Stage15 工作参考与失败账本已冻结
FQ empty 和 recovery bubble 已显著收敛
四宽 commit slot3 使用率高
Head Wait Load/Store 不再主导
CDB/PRF/RS credit 成为可测瓶颈
```

若前端平均供给仍不足 4，或者 Store/Load 仍堵 ROB head，六宽只会增加接口和时序成本。

## 2. 为什么不做六宽全连接

六条指令、每条两个源操作数，直接统一 PRF+全广播需要：

```text
12 个 operand read
6+ result producer
每个 RS entry 比较所有 wakeup tag
全局 oldest select + 多 bank write conflict
```

推荐两个 cluster：

```text
Cluster 0: 3-wide dispatch, local RS, integer/control preference
Cluster 1: 3-wide dispatch, local RS, integer/memory preference
Global: ROB order, rename map, oldest exception/redirect
```

FU 归属由计数决定，preference 不是固定绑定。

```scala
class ClusterCredit extends Bundle {

```

steering 先保持程序包连续前缀和特殊边界，再按 FU 类型、源操作数 home bank 和 credit 选择 cluster。禁止在 Core 中组合扫描所有 cluster 的所有 RS 槽。

## 4. PRF 与跨 cluster 依赖

- 物理寄存器按 tag 低位映射 home bank。
- rename 记录目的 phys 的 home cluster/bank。
- 同 cluster 结果本地 bypass 和写 bank。
- 跨 cluster 结果进入有界 forwarding queue，携带 `{phys,data,robAge,generation}`。
- producer 只有在本地完成和必要远端投递都获得 owner 后才能报告 completion。

forwarding queue 必须有 backpressure；不能让 ROB done 早于远端 consumer 可见。

## 5. 六路 rename/ROB/commit

同拍 lane0..5 依次构造 temporary RAT：

```text
laneN source = 看见 lane0..N-1 的新映射
同拍 WAW    = 最年轻映射进入 speculative RAT
oldPhys     = 每 lane 保存覆盖前映射
```

commit 只提交连续前缀。lane2 异常时 lane0/1 可提交，lane2 产生精确异常，lane3..5 不提交。多个 redirect/violation 同拍仍选择程序序最老者。

## 6. control 与 memory admission

六宽不等于六 LSU：

1. 第一门保持最多一 control、已有 Load/Store service，验证主干。
2. `branch ready wait` 成为主因后再加第二 BRU。
3. L1D bank credit 允许后再增加 Store update 或第三 Load。
4. 每个限制都必须有 admission counter，不能静默把六槽 packet 压成单发。

## 7. 施工切片

| 步 | 内容 | 退出条件 |
|----|------|----------|
| 1 | WIDTH=4/6 rename/ROB/commit 模型 | WIDTH=4 等价，WIDTH=6 随机模型通过 |
| 2 | 2x3 cluster credit/steering | 六普通 ALU 可同拍 dispatch |
| 3 | banked operand/local completion | 本地依赖链无额外全局气泡 |
| 4 | cross-cluster forwarding | generation/backpressure 正确 |
| 5 | memory/control admission | 异构压力与 oldest recovery 通过 |
| 6 | 六槽前端供给 | lane4/5 fetch/dispatch/commit 非零且 cycles 下降 |
