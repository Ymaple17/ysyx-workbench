# 阶段 13e：分布式完成网络

## 学习导航
- **理论目标**：区分“指令必须先进入 RS 再等一拍发射”的固定延迟和“多个 FU 同拍完成”的结果带宽冲突。
- **最小实现**：RS 保持 resident-first oldest 选择；空闲 FU 可在 dispatch 当拍接受 ready fresh entry。完成网络扩为三个 oldest-first CDB，并保持统一 identity acceptance。
- **当前参考核**：两个 ALU、LSU、DIV 和独立 BRQ；RS fresh issue 在 Stage13f 使用 `241331` 次，CDB3 将冲突降到 `128`。普通 control/store 继续走私有完成 sideband。
- **后续扩展**：Stage14 的四 ALU、四槽 operand read、四条完成 lane、banked PRF 或 clustered backend。
- **验收方式**：resident/fresh 竞争、同包 RAW、older store/load、CDB wake、flush/reuse 和多 producer 同拍完成定向测试；严格 cycles 正收益。

---

## 1. Fresh issue

传统路径是：

```text
dispatch -> RS write -> next-cycle select -> FU register
```

当前旁路允许已就绪的新指令在 FU 没有 resident 候选时当拍进入 FU：

```scala
val freshCanIssue = freshAccept && src1Ready && src2Ready && !waitOlderStore
val issueBits = Mux(residentValid, residentEntry, freshEntry)
```

关键规则：

- resident oldest-ready 优先，fresh 不抢占已等待的老指令。
- lane0/lane1 fresh 仍按程序序和 FU 能力分配。
- 同一 dispatch packet 中，未解析的 lane0 store 会阻止 lane1 load 越过。
- fresh 指令仍分配 RS entry，并在成功旁路后标记 `issued`，保证 flush/identity 生命周期一致。
- CDB0/1/2 的同拍 wake value 可让 fresh source 立即变 ready。

该改动把 IPC 从 `1.4387` 提到 `1.4895`，节省 `12368` cycles，是 Stage13 最大的后端收益。

## 2. 三路完成网络

`WritebackArbiter` 参数化为多输出 oldest-first 选择：每选出一个 winner，就从后续选择 mask 中删除它。三个 accepted lane 分别更新 PRF、BusyTable、ROB、RS/BRQ wake/free；同一个 accepted identity 门控所有副作用。

```text
accepted = producer.valid
        && ROB entry valid
        && dynamic identity matches
        && !killed_by_flush
        && completion lane ready
```

CDB3 单独只把 IPC 从 `1.3798` 提到 `1.3824`，说明大部分冲突并不在提交关键路径。它仍被保留，因为收益为正、协议已经参数化，并为 Stage14 增加完成带宽打基础。

## 3. 分布式职责

```text
RS        本地 resident/fresh 选择和 issued 生命周期
BRQ       本地控制流选择与 wakeup
WbArb     只做 producer age/credit 仲裁
ROB       只验证身份并记录 done/value
PRF/Busy  只接受已经 identity-validated 的写回 lane
```
