## 1. 现状（阶段 6 留下的）

```text
BHT：pc 哈希 → 2bit 饱和计数器（bp_taken/bp_target）
RAS：call 压栈 / ret 弹栈（@commit 更新）
每拍只预测 1 条：pc → next_pc
```

问题：
- **BHT 冲突**：不同 pc 同一索引互相踩，预测率 55–65% 就上不去了
- **间接跳转（jalr）**：除 ret 外没有目标预测，只能等 EX
- **每拍 1 预测**：2 发射时 FQ 灌不满

## 2. TAGE（TAgged GEometric predictor）

### 2.1 原理

用**多张表**，每张表按「pc ^ (ghr 折叠到不同长度)」索引，表项带 **tag**：

```text
表 T0（无历史）   ：pc 直索引，2bit 饱和计数
表 T1（短历史）   ：pc ^ ghr[0:4]   ，tag=pc[高位]
表 T2（中历史）   ：pc ^ ghr[0:9]   ，tag=…
表 T3（长历史）   ：pc ^ ghr[0:16]  ，tag=…

预测时：从长历史表往短历史表找「tag 命中且计数≠弱」的最长表 → 用它
更新时：只更新命中表 + 若预测错则向更短表「补建」（分配新项）
```

- 长的表对「与长历史相关」的分支准，短的表负责普通分支
- TAGE 是现代处理器 BPU 标配（TAGE-SC、TAGE-SCL 是分支预测竞赛冠军）

### 2.2 教学实现简化

| 项 | 建议 |
|----|------|
| 表数 | 4 张（T0..T3） |
| 每表条目 | 256–1024 |
| 计数器 | 3bit（弱/强阈值 2 和 5） |
| tag 位 | 6–8 bit |
| 更新时机 | **仍 @commit**（3a 铁律不破） |
| 预测错误补建 | 命中表 + 下一短表随机/按地址取模分配 |

### 2.3 与 4a–4g 的交互

- commit 更新：分支提交时拿 `actual_taken` 更新命中表（ROB 里已有 `bp_index`——需要扩展成 `bp_tage_idx` 等，enq 时存预测命中的表号）
- **错误路径不更新**（预测是投机的，更新必须提交化）

## 3. 间接跳转预测（jalr）

### 3.1 现状

```text
jalr xN, (xM) —— 只有 ret（xM==x1 且链接 x1）走 RAS，其余等 EX 算
```

### 3.2 目标

- **ITAGE（Indirect TAGE）** 或简单 **BTB for jalr**：记录 `pc → 目标`，预测时直接用
- 命中判定放 EX：`pc_src=PC_RS2` 且目标 ≠ 预测 → mispred 重取
- 与 call/ret 区分：`jalr` 且 rs1==x1 → ret（走 RAS，不进 ITAGE）；否则走 ITAGE

## 4. 宽取指（每拍 2 条）

### 4.1 ICache 加宽

```text
现状：每拍读 1 个 32bit（IFU 单拍单指令）
目标：每拍读 2 个 32bit（或 64bit 行）
```

- ICache 数据宽 64bit，IFU 组装 `inst0/inst1 + pc0/pc1`
- **预测链**：`pc0` 预测 → 若 taken，则 `pc1` 无效（分支只占一条）；否则 `pc1 = pc0+4` 再预测
- 每拍 2 个预测器端口（或 1 个预测器 2 次查——组合查两次也行，教学核可接受）

### 4.2 FQ 接口

```scala
// 8b 后 FQ 已是可变宽度出队（Vec(2)）
// 9a 只需把 IFU 输出改成每拍 2 条（或 2 拍合 1 拍发 2 条）
enq: ifu.out(0).valid / ifu.out(1).valid  → FQ 一次入 2
```

### 4.3 分支边界

```text
如果 pc0 是预测 taken 分支：
  pc1 不存在（下一条是分支目标，下一拍取）
否则正常取 pc0+4, pc0+8
```

## 5. 接线步骤建议

1. `unit/bpu.scala`：BHT → TAGE 4 表（保留 RAS）
2. ROB enq 存 `bp_tage_sel`（命中最长表号）+ 更新用 tag
3. EX/commit 更新路径扩展：`bpu_update_*` 增加表号字段
4. jalr：ITAGE 表 + ret 判定保持
5. ICache 加宽 + IFU 双发 + FQ 双入
6. 每步跑 cpu-tests + 统计 misrate（阶段 7 的 PM 计数）

## 6. 踩坑

| 坑 | 现象 | 处理 |
|----|------|------|
| 错误路径更新 TAGE | 预测率假高但行为错 | 更新仅 commit |
| TAGE 与 BHT 混用双写 | 双驱动 | 二选一过渡：先 T0=T2bit 表 |
| 补建分配冲突 | 长表项被踢 | 命中表不分配，仅短表补 |
| jalr 目标被误当 ret | RAS 错乱 | rs1/rd 判定 |
| 双预测组合逻辑太长 | 时序爆 | 分两拍或接受 1 条/拍（9a 可选） |
