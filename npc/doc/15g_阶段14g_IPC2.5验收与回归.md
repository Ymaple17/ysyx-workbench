# 阶段 14g：IPC 2.5 验收与严格回归

## 学习导航
- **理论目标**：证明四发宽度真实转化为提交吞吐，并把功能、结构使用、性能和可重复性同时纳入最终合同。
- **最小实现**：WIDTH=2 compatibility 回归、WIDTH=4 完整回归、两次同二进制 microbench、宽度直方图和 Stage13f/Stage14 A/B 账本。
- **当前参考核**：Stage14 完成前仍以 Stage13f 为准；IPC `2.5` 是硬目标，不是预测值或可跳过的冲刺项。
- **后续扩展**：IPC 2.5 后重新画像，再决定双 LSU、clustered backend、uop cache、MMU 或多核；系统章节已后移到 Stage15。
- **验收方式**：严格 IPC `>=2.50`，四槽 fetch/dispatch/commit 实际使用，完整单测和 7/7 difftest，两次同二进制 delta `<=0.005`，零 stale/violation/warning。

---

## 1. 最终脚本

```bash
cd $NPC_HOME
scripts/stage14_final.sh
```

必须执行：

- WIDTH=2 compile/selected compatibility tests。
- WIDTH=4 compile、全部 OoOUnitTest、warning-free Chisel generation。
- 7/7 cpu-tests+difftest。
- full microbench 与同 binary repeat。
- 结构门槛、IPC/cycles、重复性和正确性门槛。

## 2. 硬门槛

```text
IPC                         >= 2.5000
cycles                      <= ceil(commits / 2.50)
repeat IPC delta            <= 0.005
dispatch lane2/lane3        > 0
commit lane2/lane3          > 0
fetch width 3/4 packets     > 0
FTQ stale recover           = 0
memory-order violation      = 0
difftest mismatch           = 0
```

同时报告平均 fetch/dispatch/commit width 和每 lane utilization。只出现过少量 lane3 不能证明持续四发，最终讲义必须解释宽度利用率。
