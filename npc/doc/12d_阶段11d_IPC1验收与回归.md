# 阶段 11d：IPC 1.0 验收与回归

## 学习导航
- **理论目标**：掌握性能优化的实验纪律：固定 workload、单变量 A/B、周期归因、正确性门槛和重复性；理解 IPC 达标不能替代 difftest。
- **最小实现**：把 11a-11c 的保留改动按依赖顺序合并，补齐阶段 11 专用计数器/解析脚本，完成编译、单测、cpu-tests+difftest 与至少两次严格 microbench。
- **当前参考核**：当前稳定基线仍是阶段 10m 的 IPC `0.6381`；阶段 11a-11c 尚未施工，因此本章也未验收，不能把 IPC 1.0 写成当前能力。
- **后续扩展**：阶段 11 严格收官后进入阶段 12 系统能力；若目标仍未达到，不把已定义的 11a-11c 缺口顺延，而是继续用本章账本定位和完成。
- **验收方式**：功能门、性能门、重复性门和文档门全部通过；最终保留点要求连续两次 IPC `>=1.0`、关键结果一致、无 HANG/ABORT/difftest mismatch。

## 1. 冻结可比较的基线

阶段 11 的基线固定为阶段 10m 严格结果：

```text
tag       = stage10m final closure
cycles    = 818892
commits   = 522548
IPC       = 0.6381
unit test = OoOUnitTest 68/68
cpu-tests = dummy/add/add-longlong/bit/load-store/shift/string 7/7
FTQ stale recover = 0
```

后续每次实验必须使用同一 microbench `mainargs=test`、同一仿真/编译方式和同一统计区间。若 workload、编译选项或 commit 口径变化，应建立新基线，不能直接和 `0.6381` 比百分比。

## 2. 四道验收门

### Gate A：结构与单元功能

```bash
cd $NPC_HOME
./mill -i mychisel.compile
./mill -i mychisel.test.testOnly unit.OoOUnitTest
```

要求：

- 编译/elaboration 无新增 warning。
- 所有既有单测和阶段 11 新单测全过；不要把总数永久写死为 68，因为本阶段会增加测试。
- ready/valid backpressure、flush、stale identity 和同拍事件均有定向覆盖。

### Gate B：架构正确性

```bash
scripts/stage9_regress.sh --mode cpu --tag stage11_candidate
```

至少覆盖现有 7 项 cpu-tests+difftest。任何 mismatch、HANG、ABORT、坏 trap 都直接淘汰候选点；性能再高也不保留。

### Gate C：性能与周期归因

```bash
scripts/stage9_regress.sh --mode microbench --tag stage11_candidate
```

一次有效结果必须同时具有：

```text
MicroBench PASS
HIT GOOD TRAP
IPC / cycles / commits 非空
无 HANG / ABORT / difftest mismatch
```

并比较完整账本，而不是只截取 IPC。

### Gate D：重复性与最终收口

```bash
scripts/stage9_regress.sh --mode full --tag stage11_final_run1
scripts/stage9_regress.sh --mode full --tag stage11_final_run2
```

两次都必须达到 IPC `>=1.0`。commits、cycles 和确定性计数器应一致；若仿真环境含随机仲裁，需固定 seed 或记录允许波动范围，并保证最低一次仍达标。

## 3. 阶段 11 周期账本

最终报告至少包含下面四列：

| 类别 | 10m baseline | 11 final | delta / 解释 |
|------|-------------:|---------:|--------------|
| cycles / commits / IPC | `818892 / 522548 / 0.6381` | 待测 | 总目标减少至少 `296344` cycles |
| head wait | `363162` | 待测 | 11a/11b 主要贡献 |
| wait store commit | `43219` | 待测 | 11b store path 贡献 |
| other no-commit | `66987` | 待测 | 11c 前端/恢复贡献 |
| slot1 commit | `177024` | 待测 | 11c 与后端持续供给 |
| DCache replay / SB full / LQ full | `54040 / 41278 / 7761` | 待测 | 11b 服务率 |
| fetch avg width / slot1 killed / flush | `1.3858 / 55860 / 18827` | 待测 | 11c 有效宽度 |
| CDB conflicts | `6904` | 待测 | 判断写回是否迁移成新墙 |

计数器分类应尽量互斥且能加总。例如 no-slot0-commit 周期应继续满足：

```text
no_commit = head_wait + wait_store_commit + empty_or_recovery_or_other
```

slot1 也应满足：

```text
slot0_commit = slot1_commit + slot1_not_ready + slot1_blocked
```

若等式不成立，先修统计定义，不能用重叠计数直接估收益。

## 4. A/B 保留规则

每个候选改动只允许三种结论：

| 结论 | 条件 | 动作 |
|------|------|------|
| 保留 | 正确性全绿，目标瓶颈下降，总周期改善 | 合入下一基线 |
| 拒绝 | 正确但 IPC/总周期退化，或错误路径/压力明显恶化 | 回退该候选，记录负结果 |
| 待解释 | IPC 波动小，局部指标相互抵消 | 补计数/重复实验，不立即叠下一个改动 |

不要同时打开 burst、2-way、4-MSHR、LQ8 和 loop predictor 后只报告最终 IPC。那样即使变快，也无法知道哪个结构必要；一旦出错也没有可恢复的稳定点。

## 5. 推荐集成顺序

```text
baseline 10m
  -> 11a counters only
  -> 11a same-cycle RS wake/select
  -> 11a LSU elastic refill
  -> 11b one-hit-per-cycle
  -> 11b burst transport
  -> 11b cache geometry A/B
  -> 11b store-hit update + write combining
  -> 11b multi-MSHR + miss merge + LQ sizing
  -> 11c branch+lane1 dispatch
  -> 11c targeted predictor work
  -> 11c wider fetch block only if counters require
  -> 11d two-run final closure
```

每个箭头都是一个可单独回归的保留点。这里允许实现过程中发现某项收益不足而拒绝它，但不允许把本阶段最小实现中的正确性缺口改名塞进阶段 12。

## 6. 达不到 1.0 时怎么继续

若 11a-11c 已按定义完成但 IPC 仍低于 1.0，按剩余周期占比选择下一刀：

| 剩余主因 | 下一步 |
|----------|--------|
| ALU dependency head wait | 查 bypass 覆盖、ALU pipeline latency、issue select critical path |
| load head wait / DCache busy | 增 MSHR/端口、优化 miss merge、检查总线并行度 |
| store commit wait | 扩大合并窗口、write-back cache、提高写通道并行度 |
| FQ empty / useful supply < 1 | 更宽 fetch block、banked ICache、多分支预测 |
| branch flush dominant | 按 PC/类型做 top-N miss profile，再设计 predictor |
| CDB conflict 新增 | 先看 result buffering/仲裁公平，再评估第三 CDB |
| ROB/RS full 新增 | 说明瓶颈已迁移，此时才重新扫描窗口 |

阶段 11 的目标是完整解决“从 0.6 到 1.0”这条主线，所以这些是本阶段内的诊断分支，不自动顺延为阶段 12。
