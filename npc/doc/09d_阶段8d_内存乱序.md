# 阶段 8d：内存乱序（StoreQueue 消歧）

## 学习导航
- **理论目标**：本章先理解：load 可越过地址已知的未提交 store **投机访存**；用 **StoreQueue 消歧模块**集中处理更老 store 的地址匹配、转发或等待；store buffer 是后续性能扩展。
- **最小实现**：封装 ROB-backed StoreQueue 查询：未知更老 store 让 load 等待，已知地址按掩码选择前递/等待/放行；RS 不再集中扫描完整 ROB。
- **当前参考核**：本章 ROB-backed SQ 是历史最小点；10a 改成独立 ROB-indexed SQ，10l 又加入 LQ/replay，默认仍不越过未知 older store。
- **后续扩展**：阶段 9 先量化瓶颈；10a 再增加独立 SQ 与 StoreBuffer，10l 补完整 load 身份和 replay。
- **验收方式**：涉及 RTL 时至少跑 `./mill -i mychisel.compile`、相关单测和 cpu-tests；涉及性能时再跑 `microbench mainargs=test` 并记录 before/after。

## 1. 现状与目标
| 项 | 5b（现状） | **8d** |
|----|-----------|--------|
| load vs 更老 store | `rob_st_pending`：任何未决 store 都挡 load 发射 | 地址已知的 store 交给 SQ；地址未知的更老 store 仍在 RS 侧保守等待 |
| store 记录 | ROB 项内 `mem_wdata/addr_ready` | 本参考核复用 ROB 项，外包给 `StoreQueue` 模块做消歧；独立 SQ 可作为后续扩展 |
| 提交写 | head store → commit SM 写总线 | 本参考核仍按 head store 提交写；store buffer 是性能扩展 |
| 部分重叠 | LSU wait | SQ 判定：覆盖/部分/无 |

## 2. SQ_SIZE 与 ROB_SIZE 关系
> 8d 阶段的 `StoreQueue` 是 ROB-backed：它没有单独分配 SQ 槽，而是读 `rob.io.entries` 做组合消歧，因此当章不需要 `SQ_SIZE` 参数。10a 已改成 `SQ_SIZE=ROB_SIZE` 的独立表；下面这一节描述的正是那条演进路线。

- 若希望最坏的“ROB 全是 store”路径也绝不额外因 SQ 满停顿，可取 **`SQ_SIZE >= ROB_SIZE`**；当前 10a+ 参考核直接按 `rob_idx` 索引并取 `SQ_SIZE=ROB_SIZE`
- 更小的 SQ（例如 ROB 的一半）也是合法设计，但必须在 rename/dispatch 前检查空槽并让新 store stall；不能一边宣称“永不满”，一边把容量减半

## 3. Store Queue 设计
### 3.1 独立 SQ 项结构与分配时机（后续扩展伪代码）
```scala
class SQEntry extends Bundle {
  val valid      = Bool()
  val rob_idx    = UInt(OoOParams.ROB_PTR_W.W)
  val addr_ready = Bool()                // EX 算好地址/数据
  val addr       = UInt(32.W)
  val wdata      = UInt(32.W)            // 原始 rs2，消歧时按 addr 对齐
  val wmask      = UInt(8.W)
}
class StoreQueue(n: Int = OoOParams.SQ_SIZE) extends Module {
  val entries = RegInit(VecInit(Seq.fill(n)(0.U.asTypeOf(new SQEntry))))
}

// 分配：rename/dispatch 成功拍，按 ROB 身份占槽；不能等 OoO issue 才分配。
when(dispatch_fire && is_store) {
  entries(dispatch_rob_idx).valid := true.B
  entries(dispatch_rob_idx).rob_idx := dispatch_rob_idx
}
when(wb_fire && is_store && !is_flush) {
  entries(byRob(wb_idx)).addr := wb_addr
  entries(byRob(wb_idx)).wdata := wb_data
  entries(byRob(wb_idx)).wmask := wb_wmask
  entries(byRob(wb_idx)).addr_ready := true.B
}
```
### 3.2 load 消歧组合逻辑（覆盖/部分/未知三分）
```scala
val ld_addr = lsu.io.in.bits.alu_result
val ld_age  = robAge(ld_rob, rob.io.head)
val hit  = Wire(Vec(SQ_SIZE, Bool()))      // 覆盖 → 转发
val wait = Wire(Vec(SQ_SIZE, Bool()))      // 部分重叠 / 地址未知 → 等
val dataV = Wire(Vec(SQ_SIZE, UInt(32.W)))
for (i <- 0 until SQ_SIZE) {
  val s = sq.entries(i)
  val sAge = robAge(s.rob_idx, rob.io.head)
  val older = s.valid && (sAge < ld_age)
  val sameWord = s.addr_ready && (s.addr(31,2) === ld_addr(31,2))
  val sm = storeMaskBytes(s.wmask, s.addr)
  val lm = loadMaskBytes(mem_rd, ld_addr)
  hit(i)  := older && s.addr_ready && sameWord && ((lm & sm) === lm)
  wait(i) := older && (!s.addr_ready || (sameWord && (lm & sm) =/= 0.U && (lm & sm) =/= lm))
  dataV(i) := storeShiftData(s.wdata, s.addr) >> (ld_addr(1,0) << 3)
}
```
- **覆盖**（load_mask ⊆ store_mask，同字）→ 转发 `s.wdata`  
- **部分/未知**（mask 相交不全盖，或更老 store `!addr_ready`）→ `st_fwd_wait`，地址齐/提交后再访存（教学核不合并）  
- 未命中任何 SQ → 正常 AXI 读

转发优先级——**最年轻（程序序最后）匹配** store，它的值才是最终写内存的值：
```scala
val bestOH = Wire(Vec(SQ_SIZE, Bool()))
for (i <- 0 until SQ_SIZE) {
  val newerHit = (0 until SQ_SIZE).map { j => hit(j) &&
    (robAge(sq.entries(j).rob_idx, rob.io.head) > robAge(sq.entries(i).rob_idx, rob.io.head))
  }.foldLeft(false.B)(_ || _)
  bestOH(i) := hit(i) && !newerHit
}
lsu.io.st_fwd_valid := hit.asUInt.orR && !wait.asUInt.orR
lsu.io.st_fwd_wait  := wait.asUInt.orR
lsu.io.st_fwd_data  := dataV(PriorityEncoder(bestOH.asUInt))
```
### 3.3 store buffer 进出队（后续性能扩展）
```scala
val sbValid = RegInit(VecInit(Seq.fill(SB_SIZE)(false.B)))
val sbAddr  = Reg(Vec(SB_SIZE, UInt(32.W)))
val sbData  = Reg(Vec(SB_SIZE, UInt(32.W)))
val sbStrb  = Reg(Vec(SB_SIZE, UInt(4.W)))
val sbHead  = RegInit(0.U(log2Ceil(SB_SIZE).W))   // 最老先出（按序）
val sbTail  = RegInit(0.U(log2Ceil(SB_SIZE).W))
when(cm_fire && cm_is_store) {                    // 入队：head 不堵后续提交
  sbValid(sbTail) := true.B
  sbAddr(sbTail)  := cm_bits.mem_addr
  sbData(sbTail)  := cm_bits.mem_wdata << (cm_bits.mem_addr(1,0) << 3)
  sbStrb(sbTail)  := cm_bits.mem_wmask(3,0) << cm_bits.mem_addr(1,0)
  sbTail := sbTail + 1.U
}
when(sbValid(sbHead) && bus_idle) {               // 出队：复用 5a AXI 写通道
  // 发 AW/W，并保持该项有效；只有 B 握手后才清 valid、head++。
}
```

store 从 SQ 提交到 StoreBuffer 后，年轻 load 仍必须查询 StoreBuffer：完整覆盖则按最年轻 older store 前递，部分覆盖则等待/合并，不能在 buffered store 尚未写到内存时直接读 DCache。

**同地址合并不是可直接套用的小优化**。只有证明两项之间没有会观察中间值的 load/MMIO/fence、正确合并字节 mask，并保持按序可见性后才能覆盖旧项；最小实现应让 buffer 严格按序出队，不做合并。

## 4. 与 5b 的 diff：rob_st_pending 缩小后谁负责正确性
| 5b 机制 | 8d 替代 | 正确性由谁保证 |
|---------|---------|----------------|
| `rob_st_pending` 挡 load 发射 | 只表示“更老 store 地址未知”；地址已知后不再挡 | RS 防止未知地址占住单 LSU；SQ 负责地址已知后的转发/等待/放行 |
| 扫 ROB entries 前递（`addr_ready/mem_wdata` 在 ROB 项） | 扫 SQ | SQ 只存未提交 store，匹配/age 判定逻辑不变 |
| 转发选「最老匹配」 | 选「最年轻匹配」（最后写者） | 连续 store 同地址在飞时必须给**最后**的值（5b 会给旧值，8d 修正） |
| commit SM head 直发写总线（head 等 b） | 8d 保持不变；10a 后续接 store buffer | 正确性仍由顺序提交保证，buffer 只改善提交端等待 |

关键变化：挡的位置从「**所有 store 都在发射前挡**」缩小为「**只有更老 store 地址未知时挡**」。地址一旦算出，load 不再被 ROB 扫描保守卡住，是否等待/转发/放行交给 SQ 的组合消歧。

## 5. 边界与 MMIO（store buffer 扩展时再加 drain）
```scala
val s_IDLE :: s_DRAIN :: Nil = Enum(2)
val sb_sm = RegInit(s_IDLE)
val fence_need = cm_is_fencei || cm_is_mret || head_is_exc
when(sb_sm === s_IDLE && fence_need && sbNonEmpty) { sb_sm := s_DRAIN }
when(sb_sm === s_DRAIN && sbEmpty) { sb_sm := s_IDLE }
fencei_commit_ready := (sb_sm =/= s_DRAIN) || sbEmpty   // 4f：drain 完才提交
val mmio = cm_is_store && (cm_bits.mem_addr >= MMIO_BASE)
mmio_ok := (sb_sm === s_IDLE) && sbEmpty                // MMIO 直发，须 buffer 空
```

## 6. 时序（示例）
```text
T：sw x1, 0(a0)（issue，SQ 项#0）；lw x2, 0(a0)（越过 store 发射）
T+1：SQ#0 addr 算好 = a0+0，wdata=x1
     LSU 查 SQ：匹配 #0（覆盖）→ 转发 x1 给 lw（零访存）
T+2：lw 写回；sw 等 head 提交 → 走原提交写通路
```

## 7. 微测清单扩展
| 用例 | 期望结果 |
|------|----------|
| 同字覆盖：`sw x1,0(a0)` → `lw x2,0(a0)` | 转发 x1，零 AXI 读 |
| 部分重叠：`sb` + `lw` 同字 | `st_fwd_wait`；store 提交后读内存 |
| 跨字：`sw @0` → `lw @4` | SQ 无匹配 → AXI 读 |
| 未知地址：load 越过未算完 store | wait 拉住，地址齐才发 AR |
| 连续 store 同地址：`sw x1; sw x2; lw` | 转发**最后写者** x2（最年轻匹配） |
| 连续 store 不同地址 | 各命中各转发，互不干扰 |
| lbu/lhu 从 store 转发 | `fwd_ext` 符号/零扩展正确（不得 0xffffff80） |
| store 已提交、buffer 未出 | load 查询 StoreBuffer：匹配则前递/等待，禁止读到旧内存 |
| unalign：`sw @1` + `lw @0` | 字节 mask 判部分重叠 |
| MMIO store 后跟 load | 8d 按顺序提交保序；10a 加 store buffer 后仍令 MMIO 直发并处理 drain（§5） |

## 9. 踩坑
| 坑 | 现象 | 处理 |
|----|------|------|
| 地址未知 store 挡 load | 还是堵（等价 mem@head） | 教学先「等地址」；地址预测选做 |
| 两个同地址 store 在飞 | 转发了最老 store 的旧值 | 转发**最年轻匹配**（最后写者胜） |
| 转发 wdata 未扩展 | lbu 得 0xffffff80（5b 已踩） | 复用 `fwd_ext` |
| 未证明条件就合并同地址 store | 丢失中间可观察值或字节 mask | 最小实现不合并；先保证按序出队和 load/SB 转发 |
| fencei 前没 drain | 自修改失效 | 8d 无 store buffer；10a 后 fence 与写队列互斥（§5） |
| MMIO 进 buffer | 串口字符乱序/丢 | 8d 无 store buffer；10a 后 MMIO 仍直发（§5） |
| SQ 满 | 新 store 卡 issue | 8d ROB-backed SQ 不会额外满；当前独立 SQ 取 `SQ_SIZE=ROB_SIZE` |

## 阶段 8d 快照实现对照
阶段 8d 快照把消歧逻辑从 core 的分散 ROB 扫描封装到 ROB-backed `StoreQueue`，核心文件是：

- `work/remote_repo/scala/unit/sq.scala`
- `work/remote_repo/scala/core/lsu.scala`
- `work/remote_repo/scala/core/core.scala`
- `work/remote_repo/scala/unit/rs.scala`

最关键的是 SQ 自己判断“等 / 转发 / 放行”：

```scala
val olderStore = e.valid && e.mem_valid && e.mem_write && (eAge < ldAge)
val unresolved = olderStore && !e.addr_ready
val sameWord = e.addr_ready && (e.mem_addr(31, 2) === io.ld_addr(31, 2))
val storeMask = storeMaskBytes(e.mem_wmask, e.mem_addr)
val loadMask = loadMaskBytes(io.ld_mem_rd, io.ld_addr)
val fullCover = (loadMask & storeMask) === loadMask
val overlap = (loadMask & storeMask) =/= 0.U
waitHits(i) := io.ld_valid && (unresolved || (olderStore && sameWord && overlap && !fullCover))
fwdHits(i) := io.ld_valid && olderStore && sameWord && fullCover
```

然后 `core.scala` 把 SQ 结果喂给 LSU，同时给 RS 一个更窄的 unresolved-store bitmask：

```scala
lsu.io.st_fwd_valid := sq.io.fwd_valid
lsu.io.st_fwd_data  := sq.io.fwd_data
lsu.io.st_fwd_wait  := sq.io.wait_load
rs.io.rob_st_pending := VecInit((0 until OoOParams.ROB_SIZE).map { i =>
  val e = rob.io.entries(i)
  e.valid && e.mem_valid && e.mem_write && !e.addr_ready
}).asUInt
```

RS 里的策略对应为：

```scala
val waitOlderStore = entries(i).valid && entries(i).lsu_mem_valid &&
  !entries(i).lsu_mem_write && hasOlderPendingStore(entries(i).rob_idx)
canIssue(i) := ready && !waitOlderStore
```

这就是阶段 8d 快照的实际分工：RS 不再按“所有更老 store”粗暴阻塞 load，只挡未知地址；LSU 负责真正访存；ROB-backed SQ 封装地址已知后的“等 / 转发 / 放行”。当前阶段 10m 已进一步换成 dispatch 分配的独立 ROB-indexed SQ，并加入 StoreBuffer 查询与 LoadQueue/replay；本段代码用于理解 8d 最小演进点，不代表最终模块形态。
