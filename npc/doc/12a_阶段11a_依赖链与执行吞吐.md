# 阶段 11a：依赖链与执行吞吐

## 学习导航
- **理论目标**：理解“FU 能每拍接收”不等于“依赖链能每拍前进”，掌握 CDB 同拍 wakeup-select-bypass 和弹性流水 `pop+push` 的时序。
- **最小实现**：为 RS 增加同拍 CDB 有效就绪/数据旁路；让 ALU 与 LSU 地址前级在旧项离开时同拍接收新项；补充分类型 head-wait/issue 气泡计数器。
- **当前参考核**：**已实现**。RS 用 `issueEntries` 组合叠加两条 accepted CDB 的 ready/value，同拍参与四类 oldest-ready 选择；`d_alu0/d_alu1/d_div/d_lsu` 与 LSU 地址 skid 均支持安全 pop+push。无目的寄存器的普通控制流还可通过独立 sideband 直接完成 ROB/释放 RS，不再占数据 CDB。
- **后续扩展**：更深流水、clustered scheduler、第三 CDB 或 value prediction 只在新的计数器证明必要时再做，不属于本章最小实现。
- **验收方式**：双 CDB 同拍唤醒、两个源命中、flush/ROB 复用身份、LSU 连续地址生成和直接控制流完成均有定向覆盖；整机回归再比较 `RS CDB Wake-Issue`、`LSU Address Refill`、head wait 和 IPC。

## 1. 阶段 10m 的气泡在哪里

阶段 10m 已支持 FU 结果离开时给 ALU/DIV dispatch register refill，但当时 RS 逻辑的本质仍是：

```text
cycle N:   producer result appears on CDB
edge N:    RS entry.src_ready := true
cycle N+1: selector sees ready and issues consumer
```

对于 `add x1,...; add x2,x1,...; add x3,x2,...` 这样的依赖链，CDB 已经携带值，消费者却多等一个选择周期。`Head Wait=363162` 很大，但先要用分类型计数器确认其中有多少是这种依赖/执行气泡。

LSU 还有另一类局部气泡：地址前级在当前项离开时不能同拍 `pop+push`，相邻 load/store 即使源都 ready，也不能连续进入地址生成。以上两点都是本章的历史输入，不再是阶段 11d 参考核现状。

## 2. 同拍 wakeup-select 的正确语义

### 2.1 有效 ready

对每个 RS entry 和每个源，组合地产生：

```scala
val src1Hit0 = io.cdb(0).valid && io.cdb(0).bits.pdest === entry.psrc1
val src1Hit1 = io.cdb(1).valid && io.cdb(1).bits.pdest === entry.psrc1
val src1ReadyEff = entry.src1Ready || src1Hit0 || src1Hit1
```

`src2` 同理。selector 使用 `srcReadyEff`，寄存器中的 `srcReady` 仍在时钟沿更新，供下一拍和停顿时保存。

### 2.2 有效操作数

如果 entry 在被 CDB 唤醒的同一拍被选中，它不能再读旧 PRF 值：

```scala
val src1ValueEff = Mux(src1Hit1, io.cdb(1).bits.data,
                   Mux(src1Hit0, io.cdb(0).bits.data, entry.src1Value))
```

双 CDB 同时写同一个 `pdest` 正常情况下不应发生，但仍要定义固定优先级并用 assertion 抓住协议错误。

### 2.3 身份门控

CDB 旁路必须沿用阶段 10 的 accepted writeback identity：

```text
valid + rob_idx + pc + arch_rd + pdest
```

仅比较 `pdest` 或 `rob_idx` 都可能让 flush 后的迟到结果唤醒已复用的 entry。RS 看到的 CDB 应是 WBU/ROB 已确认接收的结果，而不是 FU 的原始 `out.valid`。

## 3. 保持分布式选择

不要为了同拍唤醒改成一个集中式全局 issue arbiter。每个端口仍独立选择本类最老 ready 项：

```text
ALU0: oldest(entry.canAlu  && readyEff)
ALU1: oldest(entry.canAlu  && readyEff && notSelectedByAlu0)
LSU : oldest(entry.canLsu  && readyEff)
DIV : oldest(entry.canDiv  && readyEff)
```

同拍 CDB 只改变 entry 的局部 `readyEff/valueEff`，年龄比较和 FU 分类仍在各自 selector 内完成。这样不会引入“中央 scoreboard 决定全核”的长组合路径。

## 4. 弹性 refill

### 4.1 通用规则

一个单项流水寄存器的 ready 应写成：

```scala
val leave = out.valid && out.ready
in.ready := !validReg || leave

when (in.fire) {
  bitsReg := in.bits
  validReg := true.B
}.elsewhen (leave) {
  validReg := false.B
}
```

注意 `in.fire` 的优先级高于单独清空；这样同拍旧项离开、新项进入时 `validReg` 保持为真。

### 4.2 LSU 两处都要检查

当前 LSU 路径至少有两层需要分别支持弹性流动：

```text
RS issue -> d_lsu dispatch register -> LSU address skid -> LQ/DCache/SQ
```

只修 address skid 而 `d_lsu` 仍在 `lsu_addr_leave` 时拒绝 refill，吞吐仍会隔拍。反之亦然。每层都要用自己的 `leave` 计算 `ready`，不能由顶层拼一个全局 stall。

### 4.3 副作用只能跟 fire

SQ 地址 ready、LQ allocate、DCache request 和 perf counter 都必须绑定相应 `fire`，不能绑定 `valid`。同拍 pop/push 后 valid 可连续为真，若以 valid 触发会重复分配或重复发请求。

## 6. 组合环与优先级风险

| 风险 | 约束 |
|------|------|
| CDB → RS select → FU → CDB 形成组合环 | FU 输出必须来自寄存流水项；本拍新 issue 不能同拍生成 CDB |
| 两个 issue 端口选中同一 entry | ALU1 selector 显式排除 ALU0 winner；其他 FU 类型互斥应有 assertion |
| CDB 值与 PRF 值优先级错 | accepted CDB 命中时覆盖 entry/PRF 保存值 |
| flush 与 wakeup 同拍 | flush/kill 优先，不允许已杀 entry 发射 |
| refill 时重复 side effect | 所有分配、释放、计数仅看 `fire` |

## 8. 当前参考实现

### 8.1 RS 同拍 wake/select/value bypass

`unit/rs.scala` 不等待 entry 寄存器下一拍更新，而是为每项先构造组合视图：

```scala
val e = WireDefault(entries(i))
when(cdbHit1)  { e.src1_ready := true.B; e.src1_val := io.cdb_val }
when(cdb1Hit1) { e.src1_ready := true.B; e.src1_val := io.cdb1_val }
issueEntries(i) := e

val ready = entries(i).valid && !entries(i).issued &&
  issueEntries(i).src1_ready && issueEntries(i).src2_ready
```

所有端口仍各自在 RS 内做 oldest-ready；没有新增全核 scheduler。最终严格结果中，`RS CDB Wake-Issue=266810`，说明旁路不是死代码。

### 8.2 弹性 LSU 与直接控制流完成

`core/core.scala` 对 LSU dispatch register 使用 `lsu_addr_leave || !d_lsu_valid` 作为 refill 条件；`core/lsu.scala` 的地址 skid 也采用同样的 pop+push 规则。最终严格结果记录到 `LSU Address Refill=46150`。

对不写目的寄存器的普通 branch/jump，ALU0 在解析完成后通过 `ctrl_wb_fire` 直接标记 ROB done，并通过 `free_ctrl_fire` 释放 RS。该 sideband 带 ROB/PC 身份门控，控制流仍在 ROB 有序提交并训练 BPU；它只是绕开无意义的数据 CDB 竞争。最终结果 `Control Direct Complete=123288`。

## 9. 验收标准

### 功能

- 同拍 CDB 唤醒的消费者可在当拍被 selector 选中，拿到的操作数是 CDB 新值。
- 双 CDB、双源、双 ALU 不会重复选择或丢 entry。
- LSU 可连续地址生成；backpressure 时数据稳定且不重复请求。
- flush 后迟到结果不能唤醒、释放或完成新身份的 ROB/RS 项。

### 性能

- 新增计数器证明 wake-to-issue 和 LSU refill 真实发生。
- ALU/LSU 对应的 head-wait 周期下降；若总 head wait 不降，要解释瓶颈迁移到哪里。
- IPC 相对 10m 基线改善；不以牺牲 branch flush、replay 或错误路径工作换表面宽度。
