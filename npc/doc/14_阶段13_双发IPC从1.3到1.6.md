# 阶段 13：双发 IPC 从 1.3 走向 1.5/1.6

## 学习导航
- **理论目标**：理解双发核达到 IPC 1.3 后，怎样用严格 A/B 实验识别剩余关键路径，并把已有两槽宽度尽量转化为有效提交。
- **最小实现**：在 Stage12f 上依次验证方向预测、取指 refill、调度旁路、完成带宽与 L1 容量；只保留严格 difftest 下能减少 cycles 的通用改动。
- **当前参考核**：Stage13f 真乱序双发参考核已完成最终验收，两次 IPC 均为 `1.5134`（`345032` cycles / `522164` commits）。
- **后续扩展**：阶段 14 才拓宽到真四发；本阶段不提前声称已有四路 rename、ROB 四入队或四提交。
- **验收方式**：IPC `>=1.50` 为硬门槛、`1.60` 为冲刺目标；完整单测、7/7 cpu-tests+difftest、两次同二进制 microbench、零 stale FTQ recovery 与零 memory-order violation。

## 1. 入口与最终出口

| 指标 | Stage12f | Stage13f |
|------|----------|----------------|
| IPC | `1.3736` | `1.5134` |
| cycles / commits | `380267 / 522350` | `345032 / 522164` |
| Average Fetch Width | `1.8614` | `1.8650` |
| Commit Slot1 Util | `74.33%` | `76.83%` |
| FQ Empty / Full | `39214 / 2582` | `21550 / 1032` |
| Direction / Target / JALR | `11909 / 361 / 643` | `11586 / 439 / 410` |
| Head Wait | `27500` | `10880` |
| CDB Conflict | `8997` | `128` |
| DCache hit rate | `97.03%` | `98.02%` |

总周期下降 `35235`，约 `9.27%`；按 IPC 计算提升约 `10.18%`。收益不是来自单一“大招”，而是 refill、调度延迟、方向预测和 cache 容量共同减少了串行空泡。

## 2. 本阶段实际保留的结构

```text
Direction:  committed per-PC local history + 3-bit local PHT + chooser
Frontend:   32B ICache line uses one AXI INCR burst; ICache 16 KiB
Scheduler:  ready fresh dispatch may issue in the same cycle, resident-first
Completion: three oldest-first data CDB lanes, identity-guarded side effects
Memory:     DCache 4 KiB; retain Stage11 one active + one secondary request
```

这里必须区分“本章讨论过的完整机制”和“当前参考核真正实现的机制”。Stage13 没有实现 SC、fetch request queue 或多 MSHR bank；它们保留在各章的后续扩展中。

## 4. 保留与拒绝原则

```text
strict difftest pass
cycles 实际下降
动态 commits 变化有解释
目标 counter 同向变化
无 benchmark PC 常量
新增状态有 flush/reuse 身份保护
```

本阶段拒绝了 early-BRU bypass 和 FTQ32：前者在有效 workload 上没有收益，后者把压力移到 FQ/credit 并回退到 IPC `1.3794`。被拒绝的实验同样写入结果账本。

## 5. 分布式边界

```text
BPU/FTQ       本地维护预测 metadata 与恢复身份
ICache/FQ     本地维护 line refill 与 packet credit
RS/BRQ        本地选择 oldest resident 和 fresh candidate
LQ/DCache     本地维护 request identity/replay
ROB           只负责有序提交、精确恢复和 done 身份
```

顶层只连接资源 credit、年龄身份和 redirect 优先级，没有新增全核 stall 状态机。
