# 阶段 15c：六宽分布式后端

## 学习导航
- **理论目标**：理解从四宽到六宽时，全连接 PRF/RS/CDB 的面积与时序为何超线性增长，以及 cluster/local-credit 如何把控制靠近资源。
- **最小实现**：`CORE_WIDTH=6` 的 rename/ROB/commit 主干，两个三宽执行 cluster，本地 issue/operand/bypass/completion，跨 cluster 结果通过有界转发；全局只保留程序序与最老恢复选择。
- **当前参考核**：Stage14 是四宽、四 CDB、四 ALU 主干；Stage15a/15b 未通过 A/B 前不打开六宽。当前每拍最多一条 control，访存服务也不是六路。
- **后续扩展**：第二 BRU、双 store address、三 load bank、更宽 trace、更多 cluster；只有对应 workload 和 counters 证明需要时才增加。
- **验收方式**：WIDTH=4 等价回归、WIDTH=6 同拍 RAW/WAW/free-list/ROB wrap、cluster credit、跨 cluster wakeup、六提交异常/redirect、FU 不对称与压力随机测试；全核要求 lane4/5 实际使用且 cycles 下降。

---

## 1. 为什么不做六宽全连接

六条指令、每条两个源操作数，若直接做统一 PRF+全广播：

```text
12 read operands
6+ result producers
每个 RS entry 比较所有 wakeup tags
全局 oldest select + 多 bank write conflict
```

这会显著拉长 rename/read/wakeup/select/bypass 路径。教学核应把执行资源分成两个 cluster：

```text
Cluster 0: 3-wide dispatch, local RS, ALU0/1, branch preference
Cluster 1: 3-wide dispatch, local RS, ALU2/3, memory preference
Global: ROB order, rename map, exception/redirect oldest selection
```

具体 FU 归属由测量决定，不能把上面的 preference 写死成唯一答案。

## 2. dispatch steering

每个 cluster 导出本地 credit：

```scala
class ClusterCredit extends Bundle {
  val intSlots = UInt(...)
  val memReady = Bool()
  val bruReady = Bool()
  val wbCredit = UInt(...)
}
```

steering 先遵守程序包前缀与特殊边界，再按 FU 类型、源操作数 home bank 和 credit 选择 cluster。不能用一个巨大的全局优先编码器组合检查所有 RS 槽；cluster 只承诺“可接受几条什么类型”。

## 3. PRF 与跨 cluster 依赖

最小可行方案：

- 物理寄存器按 tag 低位 home-bank。
- rename 记录目的 phys 的 home cluster/bank。
- 同 cluster 结果本地 bypass+写 bank。
- 跨 cluster 结果进入有界 forwarding queue，携带 `{phys,data,robAge,generation}`。
- consumer 未收到远端值时保持 wait，不从架构寄存器旁路。

forwarding queue 必须有 backpressure；producer 只有在本地 write 与必要远端投递均获得所有权后才能报告 completion，避免 ROB done 早于远端依赖可见。

## 4. 六路 rename/ROB/commit

同拍 lane0..5 依次构造 temporary RAT：

```text
laneN source = 看见 lane0..N-1 的新映射
同拍 WAW    = 只有最年轻映射进入 speculative RAT
oldPhys     = 每 lane 保存其覆盖前映射，按提交/flush 回收
```

commit 保持连续前缀。若 lane2 是异常，lane0/1 可提交，lane2 触发精确异常，lane3..5 不提交。多个 redirect/violation 同拍只选择程序序最老者。

## 5. control 与 memory 宽度

六宽后端不等于第一天就有六 LSU：

- 第一门：最多一 control、最多两条不同 bank 的 load/store address，验证总主干。
- 第二门：若 `branch ready wait` 或 control queue 持续成为主因，再加第二 BRU。
- 第三门：若 L1D bank credit 允许，再放宽双 store update 或第三 load。

每个限制都由 admission counter 明示，禁止静默把整个 packet 降成单发。

## 6. 施工切片

| 步 | 内容 | 退出条件 |
|----|------|----------|
| 1 | WIDTH=6 rename/ROB/commit 纯模型 | 随机参考模型与 WIDTH=4 等价 |
| 2 | 2x3 cluster credit/steering | 六普通 ALU 可同拍 dispatch |
| 3 | banked operand/local completion | 本地依赖链无额外全局气泡 |
| 4 | cross-cluster forwarding | tag/generation/backpressure 正确 |
| 5 | memory/control admission | 异构混合压力与 oldest recovery |
| 6 | Trace frontend 六槽供给 | lane4/5 fetch/dispatch/commit 非零 |
