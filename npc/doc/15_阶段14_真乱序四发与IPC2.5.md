# 阶段 14：真乱序四发与 IPC 2.5

## 学习导航
- **理论目标**：把“宽度”拆成 fetch、rename、ROB allocate、dispatch、issue、completion 和 commit 七个独立协议，理解真四发不是增加两个 ALU。
- **最小实现**：先参数化并证明 WIDTH=2 等价，再逐步打开四槽前端、四路 rename/ROB、分布式 dispatch/issue、可扩展 operand/completion 和四提交。
- **当前参考核**：Stage13f 是已冻结的 2-wide 主干，严格 IPC `1.5134`；Stage14 RTL 未完成前，任何 4-wide 描述都只是理论目标。
- **后续扩展**：双 LSU/AGU、更多 memory ports、clustered backend、uop cache、SMT 和更宽 SIMD；不属于 IPC 2.5 最小合同。
- **验收方式**：WIDTH=2 行为等价、WIDTH=4 全回归、slot2/slot3 实际使用、四槽提交有序、严格 microbench IPC `>=2.50`、两次同二进制可重复。

## 3. 最小限制不是假能力

第一版允许：

```text
每拍最多 4 条普通整数
最多 1 条 control
最多 1 条 memory
特殊/异常/MMIO 仍独占
```

这仍可成为真四发，因为总 dispatch/issue/commit 主干为 4；“四发”不要求四个 LSU。限制必须由 lane admission 明示并计数，不能静默把整包降成单发。

## 4. IPC 2.5 周期预算

以 Stage13f 的动态 commits 为准：

```text
target_cycles = ceil(522164 / 2.50) = 208866
```

四发理论上限 4，IPC 2.5 要求至少 62.5% 有效利用率；相对 Stage13f 还要减少 `136166` cycles，因此前端、分支和 completion 必须一起扩宽。
