# 阶段 12b：热点驱动的分支预测与恢复

## 学习导航
- **理论目标**：区分方向错、目标错和未预测，理解 loop/local direction provider 与 history-tagged indirect target provider 分别解决什么问题。
- **最小实现**：针对统计证明的循环方向热点和多目标 jump table 改进 provider/chooser；继续使用 FTQ 快照恢复 speculative GHR/RAS，训练不依赖写死 PC。
- **当前参考核**：方向侧为 base/bimodal tournament + 4×256 TAGE（历史 `3/8/16/32`）+ 64-entry loop provider；间接侧为 PC alternate + 4×128 ITAGE（历史 `8/16/24/48`），并把最近两个间接目标压成 16-bit path history。GHR/path/RAS/loop iteration 均有 speculative/commit 状态和 redirect 恢复。
- **后续扩展**：统计校正器、TAGE-SC-L、更强 target cluster 和大容量表仍可研究；当前不扩大，因为 compact 结构已把 target miss 降到 `361`、unpredicted JALR 降到 `643`，容量不再是第一主墙。
- **验收方式**：分别比较 direction/target/unpredicted/flush 及 Top-PC；定向覆盖双槽预测、commit update、mispredict recover、RAS call/ret 和 FTQ generation stale reject。

---

## 1. 三类错不能混在一起

```text
direction miss:    conditional branch taken/not-taken 错
target miss:       已预测 taken，但 target 错
unpredicted:       控制流被识别时没有有效 provider
```

阶段 12a 的热点表明，方向错集中在软件乘除和 DFS/qsort 循环；间接错则高度集中在 `bench_bf_run` 的 jump table。扩大一张 direction table 不会修复多目标 `jalr`。

## 2. 循环方向 provider

最小 loop/local provider 至少保存：

```text
tag, direction/confidence, iteration count, current iteration
```

只有 tag 命中且 confidence 足够时覆盖 tournament 结果；退出预测错后降低 confidence 并学习新 trip count。实现不能按 microbench 地址特判，index/tag 都由通用 PC 和历史计算。

如果采用更小的 local-history predictor，也要由 chooser 学习它何时胜过 TAGE/bimodal。不要无条件覆盖，否则相关分支可能退化。

## 3. 多目标间接跳转

PC-only target table 对 jump table 的问题是“最后目标”不断被下一条动态实例覆盖。ITAGE 用：

```text
index = hash(PC, history)
tag   = hash(PC, longer history)
data  = target + confidence
```

阶段 12 的重点不是盲目扩表，而是确认历史是否包含区分 opcode/path 的信息、provider 是否训练及时、低 confidence 时 alternate 是否合理。`0x80001748` 只能用来定位与验收，不能出现在 RTL 条件里。

## 4. 恢复是预测器的一部分

双取指下，一拍可能推进 0、1 或 2 个分支历史位。每个 FTQ entry 保存 fetch block 进入前的：

```text
specGhr + RAS stack/pointer/count + generation
```

mispredict 时从对应 snapshot 恢复，再用该分支真实结果推进一次。错误路径训练可用于高级设计，但 speculative history 绝不能跨 flush 泄漏；stale FTQ generation 必须拒绝。

## 5. 当前源码的关键实现

路径历史显式保留最近两个目标的 hash，而不是把历史旋转到无法解释：

```scala
def pathStep(history: UInt, target: UInt): UInt = {
  val targetHash = target(17, 2) ^ target(31, 16)
  Cat(history(7, 0), targetHash(7, 0))
}
```

fetch-time metadata 打包 `GHR + path + loop hit/iteration + provider rank`，随 FQ/ROB 流动；commit 训练使用当时 provider，redirect 则从 metadata 和 FTQ 的 RAS snapshot 恢复后再推进真实结果。RTL 不含 `0x80001748` 或任何 workload PC 条件。

## 6. A/B 结果

| 点 | IPC | cycles | BP flush | target miss | unpredicted JALR |
|----|----:|-------:|---------:|------------:|-----------------:|
| BRQ fresh | `1.2092` | `431987` | `17431` | `1403` | `3771` |
| compact predictor | `1.2218` | `427539` | `16472` | `1376` | `3270` |
| Stage12f 组合点 | `1.3736` | `380267` | `12913` | `361` | `643` |

compact predictor 是独立正收益点；Stage12f 还同时包含前端和 LSU 改动，因此最后一行只能用 miss counter 说明预测质量，不能把全部 cycles 收益都算给 BPU。
