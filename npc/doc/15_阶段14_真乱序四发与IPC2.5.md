# 阶段 14：真乱序四发与 IPC 2.5

## 学习导航
- **理论目标**：把“宽度”拆成 fetch、rename、ROB allocate、dispatch、issue、completion 和 commit 七个独立协议，理解真四发不是增加两个 ALU。
- **最小实现**：先参数化并证明 WIDTH=2 等价，再逐步打开四槽前端、四路 rename/ROB、分布式 dispatch/issue、可扩展 operand/completion 和四提交。
- **当前参考核**：Stage14 已接入四槽 fetch、四路 rename/ROB/dispatch/写回/commit 主干。最新官方 microbench 保留点为 `199398` cycles、`368811` commits、IPC `1.8496`；slot2/slot3 commit 分别为 `75289/50032`。功能 PASS 已确认，但 stale/replay 和最终回归门槛尚未收口。
- **后续扩展**：先按 [15h](15h_阶段14后续IPC路线.md) 修复当前正确性计数并提高有效宽度，再考虑双 LSU/AGU、更多 memory ports、clustered backend、uop cache、SMT 和更宽 SIMD；这些不应替代 IPC 2.5 最小合同。
- **验收方式**：WIDTH=2 compatibility、WIDTH=4 全回归、slot2/slot3 实际使用、四槽提交有序、严格 microbench IPC `>=2.50`、两次同二进制可重复；当前 `1.8496` 只是一项中间测量。

## 3. 最小限制不是假能力

第一版允许：

```text
每拍最多 4 条普通整数
最多 1 条 control
最多 1 条 memory
特殊/异常/MMIO 仍独占
```

这仍可成为真四发，因为总 dispatch/issue/commit 主干为 4；“四发”不要求四个 LSU。限制必须由 lane admission 明示并计数，不能静默把整包降成单发。

## 4. IPC 2.5 周期预算

性能预算必须固定同一 microbench 二进制和计数口径。当前 Stage14 候选的动态 commits 为 `368811`，若只按当前口径计算 IPC 2.5 所需周期为：

```text
target_cycles = ceil(368811 / 2.50) = 147525
```

四发理论上限 4，IPC 2.5 要求至少 62.5% 有效利用率。当前 IPC `1.8496` 只达到理论宽度的约 `46.2%`；当前应先用同一二进制做 A/B，不能直接把不同阶段的动态 commits 相减得出收益。后续优先级和验收指标见 15h。
