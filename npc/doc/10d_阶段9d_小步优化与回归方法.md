## 1. 小步优化的边界

阶段 9 适合做：

- 计数器补齐
- backpressure 小修
- FQ / BPU / RS / ROB 参数调整
- 不改变 ISA 可见语义的调度策略小修
- 文档和回归脚本整理

阶段 9 不适合直接做：

- 独立 SQ + store buffer
- 非阻塞 cache
- 多 CDB / 2 宽 commit
- 宽取指 / TAGE / 多核

这些放阶段 10。MMU/SV32 已后移到阶段 11，先不放在当前性能优化主线里。

---

## 2. 最小工作流

```text
1. 记录 baseline
2. 提出一个假说
3. 只改一个点
4. 跑 compile / unit / cpu-tests / microbench
5. 对比 IPC 和 stall
6. 写结论：保留、回退、还是推迟到阶段 10
```

## 6. 固化脚本：`scripts/stage9_regress.sh`

Stage9d 增加了一个统一入口：

```bash
cd /home/qiu/ysyx-workbench/npc
scripts/stage9_regress.sh --mode quick --tag my_change
```

常用模式：

| 模式 | 内容 | 适用场景 |
|------|------|----------|
| `compile` | 只跑 `./mill -i mychisel.compile` | 刚改 Chisel，先排除类型/连线错误 |
| `cpu` | 跑指定 cpu-tests | 快速确认 difftest 正确性 |
| `microbench` | 跑 `microbench mainargs=test` 并抽取 CSV | 做性能 before/after |
| `quick` | compile + cpu smoke + microbench | 普通 RTL 小改后的推荐回归 |
| `full` | compile + OoOUnitTest + cpu smoke + microbench | 准备收口或改了共享模块 |
| `parse` | 从已有 microbench log 抽 CSV | 不重新仿真，只整理历史结果 |

脚本会自动推断：

```bash
NPC_HOME=/home/qiu/ysyx-workbench/npc
NEMU_HOME=/home/qiu/ysyx-workbench/nemu
AM_HOME=/home/qiu/ysyx-workbench/abstract-machine
AMK=/home/qiu/ysyx-workbench/am-kernels
CPU_TEST_HOME=$AMK/tests/cpu-tests
```

如果你的环境不同，可以在命令前覆盖这些变量。

例子：

```bash
# 只跑一个 cpu-test
scripts/stage9_regress.sh --mode cpu --cpu-tests dummy --tag smoke_dummy

# 从已有日志抽取性能摘要
scripts/stage9_regress.sh \
  --mode parse \
  --tag old_run \
  --parse-log /tmp/stage9c_bht2048_microbench.log
```

microbench 模式会生成：

```text
build/stage9_regress/<tag>_<time>/microbench.log
build/stage9_regress/<tag>_<time>/microbench_summary.csv
```

CSV 字段包括 IPC、cycles、BPU hit、BP flush、方向错、目标错、JALR 未预测、FQ Full、FQ Empty、CDB conflict、head wait 和 store commit wait。

## 8. Stage9 收口结论

阶段 9 的作用是“测清楚再决定”，不是为了把所有高级结构提前做完。当前参考核保留的改动：

- Stage9a：统一 PerfMonitor 计数，补全前端、BPU、CDB、commit、SQ/LSU 观察点。
- Stage9b：BPU 冷启动小修，miss 分类计数，`FQ_SIZE=8`。
- Stage9c：保留 `FQ=8/BHT=1024`，拒绝 `FQ=16` 和 `BHT=2048`。
- Stage9d：新增回归脚本和 CSV 摘要流程。

下一步如果继续性能优化，建议进入 Stage10a 的 store commit 解耦；若要走前端路线，先看 Stage10d 的宽取指，再看 Stage10e 的更强方向预测器。Stage9 的数据已经说明：单纯继续加 FQ 或加 BHT 容量，收益很小甚至会反向。
