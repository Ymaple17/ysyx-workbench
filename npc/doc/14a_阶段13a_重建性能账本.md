# 阶段 13a：重建关键路径性能账本

## 学习导航
- **理论目标**：从“某事件发生多少次”推进到“结构改动是否让严格 cycles 下降”的关键路径归因。
- **最小实现**：冻结 Stage12f 的源码、binary 和 CSV；每个候选使用相同 microbench、difftest 和统计口径做单变量或有解释的组合 A/B。
- **当前参考核**：已有前端、提交、ROB-head、CDB、SB、LQ、cache 和分支分类计数；Stage13 新增 `RS Fresh Issue`，没有伪装成已实现一整套 overlap 计数器。
- **后续扩展**：增加 no-commit 事件交集、ready-candidate 宽度直方图、ROB age 和 load latency 直方图；统计不得参与功能控制。
- **验收方式**：同一候选两次结果可重复，计数器只观察行为，任何保留点同时满足 PASS、GOOD TRAP、cycles 下降和目标计数方向合理。

## 1. 冻结入口

```text
source commit     0f2994a
result root       build/stage9_regress/stage12_final_20260828_050633
IPC              1.3736
cycles/commits   380267 / 522350
unit/cpu-test    93/93, 7/7
```

动态 commits 会因预测路径和结束边界产生小幅变化，因此比较主指标是 cycles 和 IPC，同时检查提交数变化是否合理，不能只比较 IPC 小数。

## 3. 为什么没有把交集计数写成“已完成”

理想事件集合仍然有价值：

```text
no_commit && fq_empty
head_wait_load && dcache_miss
head_wait_alu && cdb_conflict
slot1_idle && ready_issue_ge_2
fq_empty_after_redirect
```

但当前 RTL 并未完整实现这些桶。当前参考核用现有分类 counter、同一 workload A/B 和最终 cycles 共同归因；讲义把 overlap 计数留为练习和后续扩展，避免文档领先于源码。

## 4. 新增观察点

```scala
val EVENT_RS_FRESH_ISSUE = 127.U(32.W)
```

最终候选记录 `RS Fresh Issue = 241331`。这个数表示 fresh bypass 被真实使用，不等于单独节省了 241331 cycles；很多发射原本会在下一拍发生，且会和前端、依赖及提交等待重叠。

## 5. 不变量

- perf DPI 只能单向观察，不能返回控制信号。
- Scala/C++ event id 同步更新。
- 任何计数器都不能直接作为 benchmark PC 特判。
- 严格结果必须来自启用 difftest 的完整 microbench。
