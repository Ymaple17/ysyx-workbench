# 阶段 13c：持续取指与跨行供给

## 学习导航
- **理论目标**：理解平均 packet width 接近 2 时，FQ empty 仍可能来自 line refill 请求串行、redirect 冷启动和 cache 容量冲突。
- **最小实现**：把 32B ICache line 的八次单拍 AXI 读改为一次 `INCR` 八拍 burst，并把 ICache 从 64 sets 扩到 128 sets；保留已有跨行双槽规则。
- **当前参考核**：ICache 16 KiB、4-way、32B line；每次 miss 只有一个 AXI AR handshake，随后接收八个 R beat。当前没有 fetch request queue、next-line prefetch 或 response epoch 队列。
- **后续扩展**：多请求 fetch queue、next-line prefetch、四槽 fetch block、uop cache 和 way prediction；四槽协议在 Stage14 实现。
- **验收方式**：burst ARLEN/RLAST、跨行命中、backpressure、redirect 定向测试；完整 difftest 下 FQ empty、miss/refill 代价和 cycles 下降。

---

## 1. 为什么 burst 能省周期

旧 refill 对一条 32B line 重复发八次 AR，每个 word 都承担地址握手和仲裁开销。当前实现一次发送 line base：

```scala
io.out.araddr := missLineBase
io.out.arburst := "b01".U
io.out.arlen := (wordsPerLine - 1).U
```

状态机在 R channel 内用 beat counter 写入八个 word，直到最后一拍完成 valid/tag 更新。总线仍只有一个 active instruction read owner，但一条 line 内不再重新仲裁八次。

## 2. 跨行双槽的真实边界

Stage12 已有 slot0/slot1 和跨行第二 word 的命中检查。Stage13 没有增加预取队列：如果 slot1 落到未命中的下一 line，它会等待正常 miss/refill；slot0 是 taken control 时仍屏蔽错误顺序的 slot1。

因此本阶段的收益来自更快填完 line 和更低容量 miss，而不是多个 fetch request 同时 outstanding。

## 3. A/B 结果

| 候选 | IPC | cycles | FQ empty |
|------|-----|--------|----------|
| CDB3 前点 | `1.3824` | `377584` | - |
| + ICache burst | `1.4387` | `363021` | `22518` |
| + RS fresh issue | `1.4895` | `350653` | `22802` |
| + ICache 16 KiB | `1.4943` | `349467` | `21709` |

burst 是 Stage13 最大的前端收益。扩大 ICache 的收益较小但为正，因此保留；FTQ16 扩到 FTQ32 则回退到 IPC `1.3794`，说明队列容量不是当时的关键路径。

## 4. 定向测试

- 一次 AR handshake 后连续接收八个 R beat。
- R channel backpressure 时 beat index 不丢失。
- refill 完成后 line tag/valid 与数据原子可见。
- 当前 PC 位于 line 尾部时 slot1 只能在下一 line 命中时有效。
- redirect 后旧 refill 可排空，但不能向错误路径发包。
