# 阶段 4：异常 / CSR / 中断 / FENCE.I 提交化（总览）

## 学习导航
- **理论目标**：本章先理解：所有 **架构可见** 的异常、CSR 写、fencei、中断效果，只发生在 **commit（或提交间隙）**。
- **最小实现**：按 4a-4g 顺序把 CSR 元数据、CSR 写、同步异常、ebreak、mret、fence.i、外部中断迁到 ROB head 或提交间隙。
- **当前参考核**：这些精确提交规则全部被阶段 10m 继承；当前仍无 U/S 模式和完整 mstatus 恢复，那属于后置阶段 12。
- **后续扩展**：阶段 5 处理内存副作用，把 store 也迁到提交并建立 load/store 顺序规则。
- **验收方式**：涉及 RTL 时至少跑 `./mill -i mychisel.compile`、相关单测和 cpu-tests；涉及性能时再跑 `microbench mainargs=test` 并记录 before/after。

## 1. 原理：精确异常

```text
1. E 之前：架构状态已全部 commit
2. E 及之后：像没执行过（不 commit，rename/ROB 回滚）
3. mepc / mcause / mtvec 符合约定语义
```

```text
对外可见的状态变化点 = 提交点，不是写回点，更不是 ID/EX「顺便一改」。
```

| 已有（3a–3d / 4b） | 本阶段继续 |
|--------------------|------------|
| 写回 ≠ 提交；BPU@commit；can_wb | 异常/fence/中断也认 commit |
| CSR 写已 commit | ecall/ebreak/mret/fencei 搬家 |
| olderCtrl | 更依赖「未提交不改架构态」 |

**不要**再发明「异常专用提交」；在现有 `commit_fire` 上加分支。

---

## 2. 为何在 EXE/ID「顺便做」会炸

| 事件 | 乱序后乱做 | 后果 |
|------|------------|------|
| 写 CSR | wrong-path 已写 | 架构 CSR 脏 |
| ecall | 只冲前端 | rename 映射错 |
| fencei | 未提交就刷 I$ | 自修改语义错 |
| 外部中断 | 夹在指令中间 | mepc 错 |

---

## 3. 提交时行为表（完整规格）

| head 类型 | 行为 |
|-----------|------|
| 正常 ALU/load | free；arch_rat；arch_rf；head++；commit_* |
| **CSR**（4b ✅） | commit 写 CSR；rd 可仍经 can_wb 写 PRF |
| **ECALL / 异常**（4c） | mepc/mcause；回滚后续；PC←mtvec |
| **EBREAK**（4d） | commit 才 DPIC / 仿真结束 |
| **MRET**（4e ✅） | PC←mepc；冲后续（本核不恢复 mstatus，对齐 NEMU） |
| **FENCE.I**（4f） | 仅 head 发 icache.fencei；ready 前停 head |
| **外部中断**（4g） | 提交间隙采样；冲在飞；mepc←下一条将提交 PC |

优先级建议：`项内 exception/ebreak > 正常提交`；外部中断仅间隙。
