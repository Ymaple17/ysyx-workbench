# 阶段 10e：高级分支预测

## 学习导航
- **理论目标**：理解前端带宽提高后，预测质量会变得更关键；方向错、目标错、未预测 jalr 都会把宽前端变成 wrong-path 生产机。
- **最小实现**：在原 BHT+RAS 上增加 2-slot 查询、tagged override 方向表、非 ret JALR 的间接目标表，并且表项/committed history 仍只在 commit 训练。
- **当前参考核**：10e 的 tagged/indirect 最小预测器已在 10j 升级为 3-table TAGE + 2-table ITAGE；10m 加入 speculative GHR/RAS 与 FTQ snapshot，阶段 11d 再加入 PC-only bimodal/TAGE tournament。本章正文仍讲最小台阶，完整实现见 10j/10m/11c。
- **后续扩展**：多历史 TAGE/ITAGE 已在 10j 落地，speculative history 与 FTQ snapshot 已在 10m 落地；后续可继续研究更长历史、loop predictor、SC、target cache 和更细的置信度策略。
- **验收方式**：`mychisel.compile`、BPU/FQ/ROB 单测、cpu-tests + difftest、`microbench(test)`；同时记录 mispredict 分类、tagged hit、indirect hit、IPC。

---

## 1. 为什么 10e 要跟在 10d 后面

10d 解决“能不能取两条”，10e 解决“取到的是不是正确路径”。前端越宽，错误预测的代价越高：同样一次 flush，宽前端可能已经把更多错误路径指令塞进 FQ/ROB。

阶段 9 的数据已经提示过方向预测是主要瓶颈；阶段 10d 的 A/B 又说明，盲目打开 slot1 会退化。所以 10e 先做一个低风险预测器升级，而不是直接上完整 TAGE。

## 2. 10e 本章 BPU 结构

`unit/bpu.scala` 在 10e 阶段快照中的结构是：

```text
base BHT/GShare 方向预测
  + RAS call/ret 预测
  + tagged override 方向表
  + indirect target table for non-ret JALR
  + 2-slot predict ports
```

构造参数支持单测缩小表项数量：

```scala
class BPU(conf: CoreConfig,
          bhtSize: Int = OoOParams.BHT_SIZE,
          indirectSize: Int = OoOParams.INDIRECT_TARGET_SIZE) extends Module
```

单测里可以用 `bhtSize=16`、`indirectSize=16`，避免 Verilator 跑完整 1024 项初始化拖慢测试。

---

## 3. 双预测端口

为了配合 10d，BPU 有两个查询位置：

```scala
predict_pc   / predict_inst   -> bp_taken,  bp_target,  bp_hit
predict_pc1  / predict_inst1  -> bp1_taken, bp1_target, bp1_hit
```

IFU 的规则仍然是 slot0 优先：

```text
slot0 predicted taken:
  使用 slot0 目标，slot1 无效

slot0 not taken:
  slot1 预测结果才参与 next_pc
```

注意：双端口只影响预测查询。预测器状态更新仍然放在 commit，避免错误路径污染 BHT/RAS/tagged/indirect 表。

---

## 4. Tagged Override 方向表

原来的 BHT 只有索引，没有 tag，不同 PC 很容易互相覆盖。10e 阶段加了一张轻量 tagged override 表；10j 后已升级为三张 TAGE 表：

```text
tagged_valid
tagged_tag
tagged_ctr   // 2-bit 饱和计数
```

预测时：

```text
base_taken = BHT/GShare(pc)
if tagged_valid[index] && tagged_tag[index] == tag(pc):
  final_taken = tagged_ctr[index].msb
else:
  final_taken = base_taken
```

更新时：

```text
if 该分支第一次训练，或 base 方向与真实方向不一致:
  分配/更新 tagged entry
else:
  更新已有命中 entry
```

这不是完整 TAGE：没有多张几何历史表，也没有 provider/alternate 选择。但它已经教会两个关键概念：

- 用 tag 降低别名污染
- 用 override 表修正 base predictor 的顽固错误

---

## 5. 间接跳转目标表

原先非 ret 的 `jalr` 基本等到执行阶段才知道目标，前端会被动 flush。现在 BPU 对非 ret JALR 增加目标表：

```text
itt_valid
itt_tag
itt_target
itt_conf   // 2-bit confidence
```

策略：

- ret 仍然优先走 RAS
- call/普通 jal 仍按已有逻辑预测
- 非 ret JALR 在表项命中且 `conf == 3` 时预测目标
- commit 时用真实目标更新表项和置信度

这里的真实目标来自 ROB 新字段：

```scala
actual_target
```

执行写回时由 WBU 把 `next_pc` 写入 ROB；提交时 `core.scala` 把 `actual_target` 送回 BPU。

---

## 6. Commit 更新路径

预测器仍然只在提交点更新：

```text
IFU 预测 -> FQ/ROB 记录 bp_* meta
EX/WBU 写回 actual_taken / actual_target
ROB head commit
core.scala 驱动 bpu_update_*
BPU 更新 BHT/RAS/tagged/indirect 表
```

这条路径保持了精确性：错误路径指令可以被 fetch、decode、甚至执行，但不会在提交前训练预测器。

## 8. 10j 如何升级成多历史 TAGE/ITAGE

本章实现适合 10e 教学闭环，但不是现代高性能核的最终形态。后续路线分三步：

1. **TAGE 方向预测**：10j 已完成 3 张几何历史表、provider/alternate、usefulness 和受控分配。
2. **ITAGE**：10j 已完成 PC-only alternate target + 2 张历史 tagged target 表。
3. **Speculative history + FTQ**：10m 已完成；预测时投机更新 GHR/RAS，flush 时按 `ftqIdx + generation` 恢复 snapshot，并只截断年轻 FTQ 项。

10f/10g 已先补最小 2-wide retire 和 ROB32，10j 实测 IPC 从 `0.4342` 小升到 `0.4357`。收益仍被低 slot1 fetch/commit 利用率限制，详见 10j。
