# 阶段 12f：IPC 1.3 验收与严格回归

## 学习导航
- **理论目标**：把性能目标转成可重复、可归因、带正确性门槛的工程验收，而不是挑选一次最快结果。
- **最小实现**：冻结 Stage12 源码和参数，跑全量单测、7 项 cpu-tests+difftest、两次同一 microbench 二进制，并生成 baseline/final 周期账本与源码哈希。
- **当前参考核**：Stage12f 已通过最终验收：Mill compile、`OoOUnitTest 93/93`、warning-free Chisel generation、7/7 cpu-tests+difftest，以及两次同二进制 microbench；两次均为 IPC `1.3736`（`380267` cycles / `522350` commits）。
- **后续扩展**：验收后依据最终 head wait、frontend、branch、CDB、cache/LQ 指标选择阶段 13 之前是否还有性能支线；MMU/多核仍是独立系统主题。
- **验收方式**：`OoOUnitTest` 全过、cpu-tests+difftest 全过、microbench PASS+GOOD TRAP、两次关键字段一致、IPC `>=1.3`、无 stale/violation/FTQ recover 错误和 warning。

## 1. 正确性门槛

```bash
cd $NPC_HOME/oood_chisel_vsrc
./mill -i mychisel.compile
./mill -i mychisel.test.testOnly unit.OoOUnitTest

cd $NPC_HOME
scripts/stage12_final.sh
```

cpu-tests 至少包括：

```text
dummy add add-longlong bit load-store shift string
```

每项都要启用 difftest。出现 mismatch、HANG、ABORT、assert、stale load response、memory-order violation 或 FTQ stale recover 非零时，性能数字无效。

## 2. 性能门槛

```text
MicroBench PASS
HIT GOOD TRAP
IPC >= 1.3000
cycles <= ceil(commits / 1.3)
```

两次运行使用同一 ELF 和同一生成模型。除 tag、时间等非功能字段外，cycles/commits/IPC 和关键事件必须一致；若模拟器本身引入非确定性，要记录允许波动范围和来源，不能只保留最快一次。

## 4. 可执行门槛

`scripts/stage12_final.sh` 除调用 full regression 外，还要求两轮分别满足：

```text
IPC >= 1.30                 cycles <= 401826
Average Fetch Width >= 1.80 Commit Slot1 Util >= 70%
Target Miss <= 500          Unpredicted JALR <= 1000
FQ Full <= 5000             Head Not Ready <= 30000
DCache Hit Rate >= 97%      FTQ Stale Recover = 0
Mem Order Violation = 0
```

它还要求 BRQ lane1、store direct completion、elastic LSU refill、ITAGE 和 loop provider 的使用次数均大于零，防止参数保留但结构实际未接通。

若完整运行已经结束、只需在修改门槛脚本后复核现有日志，可显式使用：

```bash
STAGE12_REUSE_ROOT=/absolute/path/to/stage12_final_YYYYMMDD_HHMMSS \
  scripts/stage12_final.sh
```

这个变量不会成为默认捷径；不设置时脚本仍执行 full regression 和同二进制复跑。
