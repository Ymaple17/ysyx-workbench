# 阶段 12：从 IPC 1.0 走向 1.3

## 学习导航
- **理论目标**：理解 IPC 越过 1.0 后，优化对象会从单一吞吐墙迁移为 load 关键路径、有效前端宽度、控制流恢复和分布式执行资源之间的重叠周期。
- **最小实现**：先建立按指令类型和 PC 聚合的周期账本，再依次完成 load 响应直通、双取指信用修正、热点分支预测和独立 BRU，最后只按新账本补强剩余主墙。
- **当前参考核**：阶段 12f 已通过 `stage12_final.sh` 完整回归，两次同二进制 microbench 均为 IPC `1.3736`（`522350 / 380267`），比 IPC 1.3 的固定预算少 `21559` cycles。
- **后续扩展**：阶段 13 先按新水位完成双发 1.5/1.6，阶段 14 再参数化为真四发，阶段 15 继续 Trace/L1D/六宽性能结构；MMU/SV32 和多核一致性后移到阶段 16。
- **验收方式**：每个改动都必须有同一 microbench 的 A/B 数据并通过 Mill、定向单测和 cpu-tests+difftest；12f 还要求重复运行、IPC `>= 1.3`、无 stale response/内存序错误和新增 warning。

## 1. 周期预算

阶段 11d 的稳定基线：

```text
commits = 522374
cycles  = 516339
IPC     = 1.0117
```

若动态路径近似不变，IPC 1.3 对应：

```text
target_cycles    = ceil(522374 / 1.3) = 401826
cycles_to_remove = 516339 - 401826   = 114513
reduction        = 22.18%
```

这 11.45 万周期不能通过“把 ROB 再扩大一倍”凭空消失。阶段 12 必须先确定哪些等待位于提交关键路径，哪些只是与它重叠的压力事件。

## 2. 阶段 12a 诊断基线

行为不变的 PC/cause 计数器给出以下事实：

| 指标 | Stage11d |
|------|---------:|
| Head Wait | `120998` |
| Head Wait - Load | `101360` |
| Head Wait - ALU / Store / Control | `12814 / 5416 / 1408` |
| Fetch Slot1 Credit Block | `154469` |
| Fetch Queue Empty | `61348` |
| Branch Ready Wait | `27033` |
| Direction / Target / Unpredicted miss | `12277 / 1402 / 3771` |
| CDB blocked | `7279` |
| ROB Full / RS Full | `0 / 0` |

结论是：第一主线是 load 的固定服务延迟，第二主线是前端持续供给，第三主线才是控制流预测和执行端口竞争。ROB/RS 容量不是当前入口。

## 4. 实测收敛路径

| 保留点 | IPC | cycles | 主要变化 |
|--------|----:|-------:|----------|
| Stage11d | `1.0117` | `516339` | 阶段 12 行为不变基线 |
| LQ 直通 | `1.0740` | `486437` | response/forward 直上 CDB，背压时落盘 |
| 前端 + BRQ + LQ | `1.2073` | `432391` | FQ credit、FetchBuffer flow、独立 BRU |
| BRQ fresh issue | `1.2092` | `431987` | 新入队 ready branch 可直接进入 BRU |
| compact predictor | `1.2218` | `427539` | 4 级历史、loop/path metadata |
| Stage12f convergence | **`1.3736`** | **`380267`** | FQ16/full replacement、predicted-path lane1、两目标 ITAGE history、弹性 LSU 地址级 |

最后一行是组合收敛点，不应伪装成单变量 A/B。可归因的证据是 counter 同向迁移：`Target Miss 1376→361`、`Unpredicted JALR 3270→643`、`FQ Full 21504→2582`、`Head Wait 53036→27500`。逐点数据见 [stage12_completion_results.csv](stage12_completion_results.csv)。

## 5. 分布式控制边界

```text
Integer RS -> ALU0 / ALU1 / LSU / DIV local oldest-ready
BranchIssueQueue -> BRU local oldest-ready

LQ -> load identity / replay / response bypass
FQ + FetchBuffer -> local credits
FTQ + BPU -> speculative history / recovery
ROB -> in-order architectural retirement only
```

顶层只连接 ready-valid、年龄身份、flush 和提交，不新增一个收集全核资源的集中式 stall FSM。独立 BRU 是一个本地 issue 类，不是第二套提交系统；LQ 直通也只是更早完成，架构状态仍由 ROB 有序退休。

## 7. 不接受的“优化”

- 只改参数、没有 A/B 和完整 difftest。
- 为了 microbench PC 写死目标或方向。
- load 数据绕过 SQ/StoreBuffer 顺序检查。
- 预测器在 flush 后保留错误路径的 speculative history。
- 把未完成的阶段 12 最小实现改名挪到阶段 13。
- 用动态提交数变化掩盖 cycles 没下降。
