# 阶段 14a：宽度参数化与双发等价

## 学习导航
- **理论目标**：理解宽度扩展前为什么必须先消除 lane0/lane1 隐式优先级，并用参数化协议保持旧配置完全等价。
- **最小实现**：引入 `CORE_WIDTH` 及派生 fetch/rename/dispatch/commit 参数，把 packet、valid、ready、ROB/rename/commit lane 改为 `Vec` 或带 count 的 bundle。
- **当前参考核**：参数已经打开到 `CORE_WIDTH=4`，并通过 `Wide*Compat` 保留旧接口的接线方式；WIDTH=2 等价性在当前提交前尚未重新执行完整回归，不能写成已验收。
- **后续扩展**：补做 WIDTH=2 compatibility 与同二进制 A/B，再继续验证四槽前端、四路 rename/ROB 和四提交；本章的参数化不等于性能收官。
- **验收方式**：WIDTH=2 编译、全部单测、7/7 difftest、microbench cycles/commits/IPC 与 Stage13f 冻结点一致，生成 RTL 无新 warning/组合环。

---

## 1. 参数关系

```scala
CORE_WIDTH     = 2 // 14a retained mode
FETCH_WIDTH    = CORE_WIDTH
RENAME_WIDTH   = CORE_WIDTH
DISPATCH_WIDTH = CORE_WIDTH
COMMIT_WIDTH   = CORE_WIDTH
```

允许施工中暂时不同宽，但每个模块必须读取自己的显式参数，不能假定所有宽度永远相等。

## 2. Packet 合同

```text
Packet {
  lanes: Vec[W, Lane]
  valid: Vec[W, Bool]
}
```

有效 lane 必须形成从 lane0 开始的连续前缀，除非模块明确支持 compact。推荐在边界统一 compact，内部使用 `count` 和前缀 valid，减少四路部分接收状态空间。

## 3. 先消除的特判

- `valid1/bits1/ready1` 改成向量。
- ROB head/head1 与 commit/commit1 改为 lane 数组。
- Rename2 的 `ratAfter0` 推广为 prefix RAT/free state。
- C++ commit0/commit1 改为循环，但 WIDTH=2 输出顺序不变。
- perf counter 从 slot1 专名扩成 per-lane histogram，同时保留旧字段兼容。

## 4. 等价验收

二进制摘要除 tag 外必须与 Stage13f 相同。若参数化导致 IPC 变化，本章不能继续打开 WIDTH=4；先找到隐含组合优先级或时序边界差异。

## 5. 验收清单（学习者自勾）

- [ ] 所有宽度由参数派生
- [ ] valid 是连续前缀或经过显式 compact
- [ ] WIDTH=2 全回归逐字段等价
- [ ] 没有为了四路先改变功能行为
