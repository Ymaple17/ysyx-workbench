## 1. 原理

### 1.1 程序员与 NEMU 看到的顺序

RISC-V 对单硬件线程有 RVWMO 内存模型。下面是本教学核选择的更保守、便于 difftest 的实现策略，不是 ISA 要求所有微架构都把访存严格串成这一形态：

```text
在同一线程内，就「已提交」的 load/store 而言，
行为与「按程序序依次访问内存」一致（再叠加你们对 MMIO 的约定）。
```

乱序执行时，**算地址/取 store 数据** 可以提前，但：

- 未提交的 store **不应** 让后续提交的 load 从内存读到「未来值」的错误版本，除非通过 **正确的 store-to-load 转发**；  
- 未提交的 store **不应** 永久改变对外内存（精确异常：异常前 store 要能「没发生过」）。

### 1.2 两个队列视角

```text
程序序：  ... older store ... load ... younger store ...
执行序：  load 可能先发到 LSU，older store 还在 RS/ROB
```

需要 **按程序序查找更老 store** 的结构：ROB 扫描或 **Store Queue（SQ）**。

## 2. 现状（阶段 5 之前 · 与代码对齐）

```text
RS：mem_valid ⇒ 仅 rob_idx == rob_head 可 issue   // mem@head
LSU：执行时直接 AXI 读/写
无 SQ；ROB.mem_* 未驱动提交写
mispred 不冲 LSU（防丢指令）→ 已 leave 的 wrong-path store 仍可能写完
```

| 场景 | 若去掉 mem@head 且仍执行时写 | 现行 mem@head 下 |
|------|------------------------------|------------------|
| 年轻 load 先于年老 store | load 可能读错 | 两者都等 head，少见 |
| 错误路径 store | 内存脏，无法回滚 | head 前少发；leave 后仍可能写脏 |
| load 占 ar 等 store | 死锁 | 较少触发 |

## 3. 设计规格

### 3.1 Store

```text
Issue/EXE：计算地址、准备数据 → 写入 SQ 项或 ROB 项
           可做 TLB/对齐检查，异常记 ROB，不写内存
Commit：head 是 store 时，对 AXI 发起写（或写入写缓冲再排到总线）
         成功后 head++
```

ROB/SQ 建议字段：

```text
mem_valid, mem_write, mem_addr, mem_wdata, mem_wmask
addr_ready, data_ready
committed / written
```

### 3.2 Load

```text
Issue 到 LSU：
  1. 算地址
  2. 查 SQ/ROB 中所有「程序序更老、未完成写内存」的 store
  3. 若存在 addr 未解析完的更老 store → 等待或重试
  4. 若完全匹配某更老 store：
       - 数据齐：转发
       - 数据不齐：等
       - 部分重叠（不同 mask）：简单核可停到 store 提交后走内存
  5. 若无匹配：发 AXI 读
Writeback：结果进 PRF（仍 can_wb）
```

「程序序更老」：比较 rob_idx 与 head 的年龄（模 ROB 距离）。

### 3.3 转发匹配

```text
地址相等（或缓存行/字粒度，教学核常用字/完全相等）
且 load 的字节使能 ⊆ store 的 wmask（否则算部分重叠）
```

### 3.4 MMIO

- MMIO load/store 往往 **不可随便投机**  
- 简单策略：MMIO 访问仅在 **接近提交** 或 **head** 时发出  
- difftest 已有 `commit_is_load` + `commit_mem_addr` skip 路径，提交写后地址仍要从 commit 导出

## 4. 结构方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| A. 只扫 ROB | 少模块 | 端口多、时序紧 |
| B. 独立 SQ | 端口清晰、易扩展 | 多一套分配/flush |
| C. 执行时写 + 检查点回滚内存 | 难，不推荐教学 | 内存检查点贵 |

**推荐教学路径**：B（SQ）或 A 先做「同字转发 + 否则等提交」。

## 5. 与 LSU / AXI

### 5.1 拆「执行 LSU」和「提交写端口」

```text
执行 LSU：load 读、store 地址生成（可写 SQ）
提交写：独立小状态机，仅 commit 驱动 aw/w
```

### 5.2 死锁避免（必写进设计）

```text
错误：load 已占用 ar 通道等待 rdata，同时等 store 提交；
      store 提交需要写通道，但总线/仲裁被 load 卡死

正确：
  - load 若因 store 冲突需要等，则 **先不发 ar**，或
  - 可 kill/取消未完成 load，让 store 提交写优先，或
  - 双通道真正并行且提交写有独立优先级
```

原则：**load 等 store 时不要死占总线资源。**

### 5.3 flush

- SQ 中错误路径 store：直接废项，**不得**再提交写  
- 已发出的 load：kill 或丢弃 rdata，can_wb=0

## 6. 和 ROB 提交的交互

```text
commit 端口扩展：
  if head is store:
    若写未完成：commit_valid 可真但 commit_fire 假（停 head），或
    commit 状态机占用多拍（教学核需明确 difftest：一指令仍一次 commit 脉冲）
```

difftest 通常要 **每条指令一个 commit 事件**。  
若 store 写总线多拍：在 **写完成的那一拍** 再打 `commit_valid`，或先 commit 寄存器状态再异步写（弱模型，需与 NEMU 一致——**本项目建议写完成再 commit**）。

## 7. 实现步骤建议

1. ROB/SQ 记录 store 地址数据，**暂时仍执行时写内存**（对照）  
2. 改为 **仅 commit 写**，load 仍直接读——测错误路径 store 冲刷  
3. 加 load 查表：匹配则转发，部分重叠则 stall 到 store 提交  
4. MMIO 保守策略  
5. 死锁场景压测（连续 load 命中未提交 store）  
6. 全 cpu-tests

## 8. 踩坑

| 现象 | 原因 | 处理 |
|------|------|------|
| 冲刷后内存已变 | store 执行时写 | 提交写 |
| load 数据偶发错 | 未查更老 store | 程序序扫描 |
| 部分 store 字节 | 当全字转发 | 判 wmask 或等提交 |
| 整机挂死 | load 占 ar 等 store | 先不发读 / 优先提交写 |
| difftest MMIO | 提交地址错拍 | commit_mem_addr 与写同一拍 |
| store 后 fencei | 与 I$ 一致性 | 阶段4 fencei + 本阶段 store 序 |
