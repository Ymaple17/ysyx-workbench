# 阶段 12a：瓶颈归因与 PC 热点

## 学习导航
- **理论目标**：掌握“事件总量、关键路径等待、PC 热点”三层性能证据，避免把重叠 counter 相加成虚假的 cycles 收益。
- **最小实现**：增加 head-wait 指令分类、前端资源/PC 等待、branch issue/ready-wait，以及 head wait/方向错/目标错/未预测/flush 的 PC 聚合。
- **当前参考核**：本章诊断版本精确复现阶段 11d 的 `516339` cycles、`522374` commits、IPC `1.0117`；计数器已被 Stage12f 继承，最终回归 IPC `1.3736`，原因账本见 12f。
- **后续扩展**：可加入 ROB-age histogram、load latency histogram 和按 benchmark 分项，但不能让统计 DPI 进入功能控制路径。
- **验收方式**：关闭统计时硬件行为不变；打开统计后同一二进制的 cycles/commits/IPC 与基线一致，PC 聚合总数不超过对应全局事件总数。

---

## 1. 为什么总 counter 不够

`Head Wait=120998` 只能说明 ROB 头没有完成，不能说明应该扩 BPU、CDB 还是 DCache。阶段 12a 把它拆成：

```text
ALU   12814
Load 101360
Store  5416
Ctrl   1408
Other     0
```

load 占 head wait 的 `83.77%`，因此“继续扩大 TAGE”不应成为第一步。与此同时，`Fetch Slot1 Credit Block=154469` 说明前端的第二槽位也存在明显保守门控；两者会部分重叠，不能直接相加。

## 2. PC 聚合接口

Scala 侧只发送事件和 PC：

```scala
PMPC(conf, clock, PC_EVENT_HEAD_WAIT, headPc, headWait)
PMPC(conf, clock, PC_EVENT_DIR_MISPRED, branchPc, dirMiss)
PMPC(conf, clock, PC_EVENT_TARGET_MISPRED, branchPc, targetMiss)
PMPC(conf, clock, PC_EVENT_UNPREDICTED, branchPc, unpredicted)
PMPC(conf, clock, PC_EVENT_BP_FLUSH, branchPc, flush)
```

C++ 侧用 `event -> unordered_map<pc,count>` 聚合，结束时按 count 降序打印前 12 项。统计代码不向 RTL 返回任何信号，因此不会成为预测或发射控制的一部分。

## 3. 热点如何解释

最集中的间接跳转是 `0x80001748`：

```asm
80001740: lw   a5,0(a5)
80001744: add  a5,a5,a1
80001748: jr   a5
```

它位于 `bench_bf_run` 的 jump table，单个 PC 产生 `3632` 次未预测和 `1260` 次目标错。PC-only last-target 很难处理多目标 jump table，应该引入历史相关 target provider，而不是为该地址写死目标。

方向错的头部集中在 `__mulsi3`、`__udivsi3`、queen/dfs 和 qsort 循环。它们适合验证 loop/local predictor 或更及时训练，而不是先扩大所有 TAGE 表。

## 4. 源码落点

| 文件 | 内容 |
|------|------|
| `unit/PerfMonitor.scala` | 新事件编号、`PcPerfMonitor` DPI blackbox、`PMPC` helper |
| `oood_chisel_csrc/include/perf.h` | 与 Scala 完全一致的 normal/PC event enum |
| `oood_chisel_csrc/cpu/perf.cpp` | PC 聚合、排序、Top-N 输出 |
| `core/core.scala` | head 分类、branch issue/ready 和 mispredict PC 上报 |
| `core/ifu.scala` | resource wait、PC wait、slot1 credit block |
| `unit/rs.scala` | 导出 control-ready 观测信号 |

事件编号是一项跨语言 ABI。Scala 与 C++ 必须同改，不能在中间插入编号后只重编一侧。

## 5. 一次真实踩坑

NPC host C++ 使用 `-std=c++11`。最初的排序 comparator 使用 generic lambda，host build 被拒绝；改为显式的：

```cpp
[](const std::pair<uint32_t, long long> &a,
   const std::pair<uint32_t, long long> &b) {
  return a.second > b.second;
}
```

讲义记录这个问题，是为了强调“Mill 编译成功”不等于 NPC host model 已经能构建。
