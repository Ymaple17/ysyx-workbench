## 1. 问题：两个核、两份缓存

```text
核 A：lw x1, 0(a0)  → A 的 DCache 缓存了该地址（旧值）
核 B：sw x2, 0(a0)  → B 的 DCache 写（新值）
核 A：再次 lw       → 若命中自己的缓存 → 读到旧值 ✗
```

cache coherence 要求对每个地址/line 的写形成一致的序列，并让各核的读遵循该序列；它不单独规定不同地址之间的全局观察顺序。message-passing、store-buffering 等跨地址行为属于 memory consistency（RISC-V 中是 RVWMO）和 fence/原子语义。

---

## 2. 一致性协议（MESI）

缓存行状态机：

| 状态 | 含义 |
|------|------|
| M（Modified） | 本核独占且已修改（脏） |
| E（Exclusive） | 本核独占未修改 |
| S（Shared） | 多核共享 |
| I（Invalid） | 无效 |

```text
读 miss：向总线发读请求 → 拿到数据 + 状态（E 或 S）
写 miss：发「读独占/无效化」请求 → 别人缓存失效 → 写（M）
写 hit（S）→ 发无效化 → 升 M
```

**关键动作**：总线上的**嗅探（snoop）**——每核监听别人的请求，若命中自己的 M/S 行则响应（提供数据或无效化）。

## 3. 两种实现路线

| 路线 | 做法 | 评价 |
|------|------|------|
| A. 总线嗅探 | 所有核共享一条总线，广播请求 | 简单；核多时带宽不足 |
| B. 目录 | 中央目录记每行归属 | 可扩展；目录存储/复杂度高 |

教学/小核：**A（总线）**。

## 4. 原子性（原子指令）

RISC-V 的 `lr/sc`、`amo`：

```text
lr.w  addr  → 读并建立 reservation（预留），不锁住 cache line
sc.w  addr, val → 若期间没人写该行 → 写成功（返回 0）；否则失败（返回 1）
```

多核下需要跟踪 reservation granule，并在其他核写入、相关本地事件或实现规定的条件发生时清除预留；`sc` 只在预留仍有效时尝试写入。其他核不会因为 LR 被禁止访问该 line，所以它不是总线锁。单核也要按 ISA 规则维护预留与失败条件。

---

## 5. 与乱序核集成注意

```text
- store 在 ROB commit 后可能仍停留在 StoreBuffer；真正进入 coherent memory system 的顺序点是 buffer drain/取得写权限的协议边界，fence 必须等待所需的旧 store 达到规范要求的可见状态
- fence 语义：fence.i / fence / sfence.vma 在总线层面要有「序」保证
- 投机 load 可以发 coherent read、填入 Shared line，甚至引起替换；它不能提前产生架构可见寄存器结果、异常或写失效副作用，flush 后旧响应也必须被身份门控
```
