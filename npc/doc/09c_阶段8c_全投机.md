## 1. 原理：olderCtrl 为什么是性能墙
现状（3d 遗留）：
```scala
olderCtrl(i) = ∃更老 valid 且 jump≠NONE 仍在 RS → i 不能发
```
后果：
- 分支一旦卡在 RS（等源），后面所有就绪指令全停 → 基本块内乱序、块间顺序  
- BPU 预测的收益被砍掉一大截：即使预测对了，年轻指令也**不能**提前执行

全投机后：
```text
beq（预测不跳）…… addi x1, x2, 1（无条件无关）
→ addi 直接发到 ALU，不等 beq 算完
→ 若 beq 预测对：addi 白赚；若错：恢复，重执行
```

---

## 2. 为什么 8c 才做：checkpoint 的收益门槛
7 之前（3d–7）`olderCtrl` 一直在挡投机：投机窗口恒为 0，checkpoint 纯亏——mispred 走 `rename.rebuild`（arch_rat 重放）虽慢，但窗口里没有可救的指令；checkpoint 成本却固定（每分支 32 项 RAT 快照 + freelist 位图），救不了指令时毫无收益。

所以 8c 必须「删墙」和「换恢复」**同拍做**；8b 双发射后窗口膨胀更快（每拍 2 条入队），rebuild 串行链（§3）开始吃时序。收益公式：**收益 ∝ 分支后已发射、本会被打掉的年轻指令数**——olderCtrl 在 → 窗口=0 → 收益=0 → 不建（rebuild 可接受）；olderCtrl 删 → 窗口=ROB → 收益大 → 必须建（否则每次 mispred 全表重放）。

## 3. 现状 rebuild 的代价分析（为什么要换掉）
当前 `core.scala` 的 flush 恢复是**组合重放**（`rb_steps` / `freeSteps`）：
```scala
val rb_steps = Wire(Vec(OoOParams.ROB_SIZE + 1, Vec(32, UInt(OoOParams.PHYS_W.W))))
rb_steps(0) := rb_base                        // 起点 = arch_rat（含同拍 commit）
for (off <- 0 until OoOParams.ROB_SIZE) {
  val take = (off.U < kept_n) && rob.io.entries(idx).valid && rob.io.entries(idx).reg_write
  for (a <- 0 until 32) {
    rb_steps(off + 1)(a) := Mux(take && (rob.io.entries(idx).arch_rd === a.U),
      rob.io.entries(idx).new_phys, rb_steps(off)(a))   // 串行：依赖上一步
  }
}
val rb_rat = rb_steps(OoOParams.ROB_SIZE)   // O(ROB×32) 串行链，ROB 越大越深
```
代价：
- **组合深度 O(ROB×32)**：ROB_SIZE 级串行步进 × 每步 32 项 Mux；`freeSteps` 同构（每步按 new/old_phys 改位图）。ROB=16 尚可，32/64 时这条链直接决定时钟周期  
- **宽发射后频率翻倍**：8b 每拍 2 条入队 → 窗口膨胀更快，mispred 次数 × 重建深度一起涨，成为关键路径  
- **方向反了**：越投机重放越贵——恢复代价随投机深度增长，必须换 O(1) 快照恢复

checkpoint 把 O(ROB×32) 重放变成**一拍并行写**：`rat(i) := cp.rat_snap(i)`（32 个独立 5bit 写）+ `freeBits := cp.free_snap`（位图直写），与 ROB_SIZE 无关。

## 4. 需要升级的三个配套
### 4.1 物理寄存器池加大
```text
N_PHYS ≥ 32（arch）+ 2 × ROB_SIZE（投机）：ROB=32 → 96；ROB=64 → 160
```
`ooo_params` 的 `N_PHYS` 与 PRF 深度、rename 位宽同步改。

### 4.2 checkpoint 恢复（替换「全表重建」）
```text
分支在 rename 时：push checkpoint（RAT 快照 + freelist 快照 + ROB 指针）
mispred 时：pop → RAT/freelist ← 快照；ROB 截断（被杀项 new_phys 快照里已含）
```
存储选择：**方案 A（教学推荐）**每分支存全 32 项 RAT（32×5bit）+ freelist 位图——面积大但逻辑直；**方案 B** 只存 delta——省面积、实现复杂。

### 4.3 RS 发射去掉 olderCtrl
```scala
canIssue(i) := ready && !(isLoad && olderStPend)  // 不再 && !olderCtrl
```
分支本身照常发射；`mis_predict` 逻辑保持（leave_ex 判定），只是不再挡年轻指令。

## 5. checkpoint 栈（Chisel 伪代码）
```scala
class CPEntry extends Bundle {
  val valid     = Bool()
  val rat_snap  = Vec(32, UInt(physW.W))          // 分支前 RAT
  val free_snap = UInt(nPhys.W)                   // 分支前 freelist 位图
  val rob_idx   = UInt(OoOParams.ROB_PTR_W.W)     // 分支自己的 ROB 项
  val br_new    = UInt(physW.W)                   // 分支 rd 的 new_phys（JAL 类）
}
val cpStack = RegInit(VecInit(Seq.fill(CP_DEPTH)(0.U.asTypeOf(new CPEntry))))
val cp_top  = RegInit(0.U(log2Ceil(CP_DEPTH + 1).W))

// push：分支 rename 当拍。快照抓寄存器当拍旧值（alloc 同步写、下拍才可见），
// 不用回滚就是「分支前」状态；只对可 mis 的分支建（有 bp_valid；JAL 可不建）
when(en_ren && is_branch && !cp_full) {
  cpStack(cp_top).valid     := true.B
  cpStack(cp_top).rat_snap  := rename.rat
  cpStack(cp_top).free_snap := rename.freeBits
  cpStack(cp_top).rob_idx   := rob.io.enq_idx
  cpStack(cp_top).br_new    := id_pdest          // 分支占的 phys 恢复时扣回
  cp_top := cp_top + 1.U
}
// pop：mispred 恢复拍，目标槽及其后全作废；重执行到分支会重新 push 覆盖原槽
when(restore_fire) {
  cp_top := restore_slot
  for (i <- restore_slot until CP_DEPTH) { cpStack(i).valid := false.B }
}
```

## 6. 恢复流程伪代码（mispred → restore → ROB 截断 → IFU redirect）
```text
拍 T（组合）：分支 leave_ex，br_done 且 is_ch ≠ 预测 或 目标错 → mis_predict=1
拍 T+1（恢复拍，flush_now）：
   ① RAT/freeBits ← cpStack(目标槽) 快照（并行写，O(1)）
      freeBits &= ~(1 << br_new)          [分支项保留 → new 仍占用]
   ② ROB 截断：flush_idx = 分支 rob_idx，younger 全清；③ IFU redirect correct_pc
   ④ RS 清 age > flush_idx（现有端口）；⑤ BusyTable：§7；⑥ cp_top 回退
拍 T+2：FQ 重取指；分支重执行 → 重新 push 覆盖旧槽
```
```scala
when(flush_now && mispred_restore) {        // 与 irq/fencei/mret 互斥
  for (i <- 0 until 32) { rat(i) := cp_restore.rat_snap(i) }
  freeBits := cp_restore.free_snap & ~(1.U(nPhys.W) << cp_restore.br_new)
  rob.io.flush     := true.B
  rob.io.flush_idx := cp_restore.rob_idx
  rs.io.flush      := true.B
  rs.io.flush_idx  := cp_restore.rob_idx
  ifu.io.correct_pc := cp_restore_pc      // flush_idx/correct_pc 已在 4c/6 接好线
}
```

## 7. BusyTable 恢复策略（按快照重建 vs 增量清）
- **方案 A：按快照重建（教学推荐）**——与快照自洽，一拍写完整个表：
  `busy.io.rebuild_mask := ~cp_restore.free_snap | keptNewBusy`（快照「非 free」∪ 保留项未 done 的 new_phys）
- **方案 B：增量清（保留现有 killBusy 路径）**——改动最小，但依赖现有 ROB 扫描的 `after` 判定，正确性由两套逻辑拼接，且与 WBU 同拍写回有竞争；组合扫描仍在，时序没省多少

---

## 8. 嵌套分支 checkpoint 栈深与替换策略
- 深度需求 = 窗口内**同时在飞**的分支数：`CP_DEPTH ≥ 分支密度 × ROB_SIZE`；全分支路径罕见，取 **CP_DEPTH = 4~8**（ROB=32 时）
- 栈满（cp_full）策略：**选项 1（教学）** cp_full 时分支入队 stall（取指停一拍），简单无歧义；**选项 2** 覆盖最老 checkpoint——若 mis 的恰是被丢分支则退化为部分 rebuild，两套路径并存，难测
- 嵌套恢复：mis 外层分支 → 内层 checkpoint 全作废，重执行后重建；恢复后栈深 = 重新经过的分支数 ≤ 原深，不会溢出

---

## 9. 与精确异常的关系（不能破坏）
- **提交仍顺序**（ROB head），异常/CSR/ebreak/fencei 的 4a–4g 语义不变  
- 投机只发生在**执行/写回**侧；`can_wb` 的 flush 门控仍靠 `rob_idx` 与 `flush_idx`  
- checkpoint 恢复要**连 ROB 一起截断**：被杀指令的 `new_phys` 通过 freelist 快照归还，BusyTable 对应位清掉（`busy.rebuild` 可简化/替换）

### 9.1 与 4c 异常 flush 的交互
- **异常不需要 checkpoint**：异常提交的指令都已 done，无投机可救；`flush_all` 后 RAT 直接 = `arch_rat`（复用 `rename.io.restore_arch`：`rat := arch_rat; freeBits := freeFromArch`），比 rebuild 更简单
- 两套恢复并存：**mispred → checkpoint restore（快）；irq/fencei/mret → arch restore（通用）**，按 flush 原因选入口
- **必须同步清栈**：`flush_all` 时 cpStack 全 invalid、`cp_top` 归零——否则陈旧 checkpoint 会被后续 mispred 误用
- 时序互斥：恢复拍与异常拍由 `stop_issue`/`flush_now` 保证不同拍（现有逻辑不变）

## 10. 时序（示例）
```text
T：rename 到 beq → push checkpoint#1（RAT/freelist/ROB 指针）；addi 越过 beq 发射 → ALU
T+k：beq 在 EX 判定 mispred
   → 恢复拍 pop #1：RAT/freelist 回到分支前；ROB 截到 beq；IFU redirect correct_pc
   → addi（已在飞）被 flush 杀，new_phys 归还（快照自带）
   → 旧 rebuild 要 O(ROB×32) 组合重放；checkpoint 一拍完事
```

## 12. 踩坑
| 坑 | 现象 | 处理 |
|----|------|------|
| checkpoint 栈深不足 | 嵌套分支错恢复 | CP_DEPTH ≥ 窗口内最大分支数（或恢复栈写回内存） |
| freelist 快照不含被杀项 | phys 泄漏 | 快照语义 = 分支前状态，天然包含 |
| 分支项 br_new 没从快照扣回 | 分支 new 被重新分配 → 双写 | 恢复时 `freeBits &= ~(1<<br_new)` |
| BusyTable 忘清被杀项 | 假 busy 死锁 | 按快照重建（§7 方案 A） |
| flush_all 忘清 checkpoint 栈 | 陈旧快照被误用 | irq/fencei/mret 同步清栈 |
| 保留 rebuild 旧路径 | 两套逻辑打架 | 二选一，测试覆盖 flush 场景 |
| 分支在 RS 里被 free 但没出 EX | checkpoint 误恢复 | 只对「已发射/已 leave」分支建 checkpoint |

## 本仓库实现对照
当前仓库里，checkpoint 恢复已经落在 `rename2.scala` 和 `core.scala` 里，相关文件是：

- `work/remote_repo/scala/unit/rename2.scala`
- `work/remote_repo/scala/unit/rs.scala`
- `work/remote_repo/scala/core/core.scala`

恢复路径分成两类：

```scala
rename.io.restore_cp := is_bp_flush
rename.io.restore_cp_idx := mis_cp_r
rename.io.cm_cp_valid := cm_fire && (cm_bits.jump =/= JUMP_NONE) && (cm_bits.jump =/= JUMP_MERT)
rename.io.cm_cp_idx := cm_bits.cp_idx
rename.io.rebuild := is_irq || fencei_flush || mret_flush
```

`rename2.scala` 里 checkpoint 是“按分支 push 一份 RAT/freelist 快照”：

```scala
when(push0) {
  cps(cpIdx0).valid := true.B
  cps(cpIdx0).rat_snap := ratAfter0
  cps(cpIdx0).free_snap := freeAfter0
}
when(push1) {
  cps(cpIdx1).valid := true.B
  cps(cpIdx1).rat_snap := ratAfter1
  cps(cpIdx1).free_snap := freeAfter1
}
```

RS 这边则把旧的 `olderCtrl` 去掉，变成纯 ready / age 选择，这样分支不再挡住年轻指令的投机执行。

最终版 checkpoint 有两个很关键的修正，建议和源码一起对照：

```scala
// mispredict：恢复分支自己的 RAT/free 快照
freeBits := withCommitFree(snap.free_snap)

// commit：老指令释放的 old phys 要补进所有还活着的 checkpoint
when(commitReleasesPhys) {
  when(cps(i).valid) {
    cps(i).free_snap := withCommitFree(cps(i).free_snap)
  }
}
```

不要把 checkpoint RAT 和“按 ROB 重建出来的 free list”混着用。这样会让快照里的 live phys 被重新放回 freelist，microbench 的 `vsprintf/qsort` 会很快打出来。

另一个坑是 checkpoint 生命周期：mispredict resolve 时只清掉更年轻 checkpoint，不立刻清掉分支自己的 checkpoint；分支真正 commit 时再按 `cm_cp_idx` 清。否则同一个 cp slot 可能被年轻分支复用，又在老分支 commit 时被误删。
