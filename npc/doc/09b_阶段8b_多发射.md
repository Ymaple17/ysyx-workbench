## 1. 原理：发射宽度由谁决定

「发射」有三个环节：

```text
取指宽度  ≥  重命名宽度  ≥  执行宽度
FQ deq 2     rename 2      FU 3 口（8a）
```

- 8a 后执行宽度已经是 3 口（≥2），但**rename 仍 1 宽**：每拍只能进 1 条，FQ 再宽也白搭  
- 8b 把 rename 提到 2：每拍 2 条指令同时重命名、写 ROB、进 RS  
- 提交可以继续 1 宽：乱序核提交带宽 ≠ 发射带宽，1 宽提交最简单且精确异常好做

## 2. 各部件加宽

### 2.1 参数

```scala
// common/ooo_params.scala
val ISSUE_WIDTH = 2  // 也叫 DISPATCH_WIDTH / RENAME_WIDTH
```

### 2.2 FQ 可变宽度出队

- `deq` 从单口变 **2 口**（或一个 `Decoupled(Vec(2, FQEntry))`）  
- 满/空逻辑不变；一次出 2 条要求 count ≥ 2，不足 2 时出一半（**可变宽度出队**）

```scala
// unit/fq.scala：沿用 head/count，出队宽度由 count 决定
val deq2_valid = count >= 2.U                        // 够 2 条才双出
val deq1_valid = (count >= 1.U) && !deq2_valid       // 不足 2 时单出
io.deq0.valid := (deq2_valid || deq1_valid) && !io.flush
io.deq0.bits  := entries(head)
io.deq1.valid := deq2_valid && !io.flush
io.deq1.bits  := entries((head + 1.U)(ptrW - 1, 0))  // 回绕：ptrW 截断
// head/count 更新：双出跳 2（截断回绕），单出跳 1
```

若用 `Decoupled(Vec(2, ...))` 单口，`bits(1)` 的有效性必须单独给出（`count>=2` 才算数），两方案等价。**重点：`deq1` 的 valid 必须单独管**，不能因为只出 1 条就把 `bits(1)` 当垃圾忽略。

### 2.3 Rename（改动最大）：双口 + 同拍组合旁路

当前 `rename.scala` 单口：`io.rs1/rs2/rd` 各一。2 宽后输入变成 i0/i1 两套，**顺序处理（程序序）：先 i0 后 i1**。关键冲突（同拍两条）：

```text
WAW 同 rd：i0 与 i1 都写 x5 → i1.old_phys = i0.new_phys（i0.new 提交时才归还 freelist）
RAW 同 rd：i1 读 x5、i0 写 x5 → i1.rs1_phys = i0.new_phys（组合旁路，不能读 RAT 旧值）
```

双口组合旁路伪代码（i1 源 = i0.new；RAT 仍一拍一写，i1 的写下一拍才生效，本拍全靠旁路）：

```scala
val i0_new  = Mux(i0_doren, new_p0, 0.U)             // i0 本拍分配（new_p0 见 2.7）
val i0_same = i0_doren && (i0_rd =/= 0.U)
val i1_rs1_phys = Mux(i1_rs1 === i0_rd && i0_same, i0_new, rat(i1_rs1))
val i1_rs2_phys = Mux(i1_rs2 === i0_rd && i0_same, i0_new, rat(i1_rs2))
val i1_old_phys = Mux(i1_rd  === i0_rd && i0_same, i0_new, rat(i1_rd))  // WAW 链
// 源就绪也要旁路：i1 源若是 i0.new，busy 位本拍刚 set → 直接判 ready
```

- **freelist**：一拍 pop 2 个；不足 2 个时 `fl_stall` 整拍停（或单发 i0）  
- BusyTable：`set` 2 个（i0.new, i1.new）

### 2.4 RS 双 enq

- `enq` 2 口（或 Vec(2)）；同一拍进 2 条  
- `issue` 已是 3 口（8a）→ 匹配  
- 满的判断：剩余 ≥2 才让 2 条都进，否则只进 1 或 stall

```scala
val freeCnt = PopCount(VecInit(entries.map(!_.valid)).asUInt)
io.enq1_fire := en_valid && freeCnt >= 1.U && !io.enq2_fire
io.enq2_fire := en2_valid && freeCnt >= 2.U
// enq 槽：PriorityEncoder 连续取两个空位（enq0=第一个，enq1=第二个空）
```

### 2.5 流水级接口（IDU）：双实例 vs 单 IDU 双宽

**双 IDU 实例**（推荐）：`idu(0)/idu(1)` 各自独立译码、各连 FQ 的 1 个出队口，译码器零改动。代价是译码面积翻倍（教学核可接受）；两个实例的 `is_stall` 必须**同拍同值**（半拍停一个会错位程序序）：

```scala
val idu0 = Module(new IDU(conf)); val idu1 = Module(new IDU(conf))
idu0.io.in.valid := fq.io.deq0.valid; idu0.io.in.bits := fq.io.deq0.bits
idu1.io.in.valid := fq.io.deq1.valid; idu1.io.in.bits := fq.io.deq1.bits
fq.io.deq0.ready := idu0.io.in.ready;  fq.io.deq1.ready := idu1.io.in.ready
idu1.io.is_stall := idu0.io.is_stall   // 同停同走
```

**单 IDU 双宽译码**：内部把两条 inst 并行译码、输出信号 ×2。面积省（共用 imm/control 查表），但 IDU 内部状态（fencei/ebreak/is_flush）全部双份接线，且耦合 FQ 出队形态。折衷：**先实例复制**，等译码本身成为瓶颈再合并。

### 2.6 ROB 双 enq（tail, tail+1 与回绕）

ROB 入队也 2 条：`enq_fire` 变 2 拍入，`enq_idx` 给 2 个（参考现 `rob.scala` 的 tail 递增）：

```scala
val enq0_idx = tail
val enq1_idx = (tail + 1.U)(ptrW - 1, 0)        // tail+1，回绕由截断自动处理
val tail_new = Mux(io.enq2_fire, (tail + 2.U)(ptrW - 1, 0), Mux(io.enq1_fire, enq1_idx, tail))
when(io.enq1_fire) { entries(enq0_idx) := e0; tail := enq1_idx }
when(io.enq2_fire) { entries(enq1_idx) := e1 } // 双发包含单发语义（enq1_fire 也在拍内成立）
count := count + Mux(io.enq2_fire, 2.U, io.enq1_fire.asUInt)
```

注意：
- `enq0_idx` 给 RS.enq0 记 `rob_idx`，`enq1_idx` 给 RS.enq1（两条的 rob_idx 必须连续）  
- **full 判定用 `count+2 <= n`**：不能 `count==n` 才挡，否则双发越界  
- 提交仍 1 宽：`commit_valid/commit_idx` 不动

### 2.7 BusyTable / freelist 双口注意事项

- **BusyTable**：`set` 从 1 个变 2 个（i0.new、i1.new），加 `set_en2/set_addr2`；`clr` 仍 1 个（8a 单 CDB 决定每拍最多 1 条写回）。同拍 set 两个相同 phys 不可能（freelist 分配的必然不同，除非 bug）。**i1 的源被旁路到 i0.new 后，busy 的读也要旁路**：`i1_ready = 旁路命中 ? true : busy(phys)`
- **freelist**：`new_p` 从单 `PriorityEncoder` 变双分配，第二个依赖第一个的屏蔽（组合链）：

```scala
val new_p0 = PriorityEncoder(freeBits)
val free1  = freeBits & ~(1.U(nPhys.W) << new_p0)   // 去掉已分配位
val new_p1 = PriorityEncoder(free1)
val fl_cnt = PopCount(freeBits)
fl_stall := fl_cnt < 2.U                            // 不足 2：单发 i0 或整拍停
```

归还（commit 的 `setBit`、flush 的 `rebuild_free`）逻辑不变，仍每拍最多 1 个。**禁止**用动态 Vec 写（现 `rename.scala` 的 `clrBit/setBit` 模式保持）。

## 3. 时序（示例）

```text
拍 T：FQ 出 2 条
      rename 同时处理：
        i0: x5 ← p_new0（old = RAT[x5]）
        i1: x5 ← p_new1（old = p_new0）← 同拍 WAW 链
      ROB enq 2；RS enq 2
拍 T+1：FQ 再出 2 条……（提交仍每拍 1 条，ROB head）
```

## 5. 踩坑

| 坑 | 现象 | 处理 |
|----|------|------|
| 同拍 WAW 没串联 old/new | x5 提交后映射错 | i1.old = i0.new（组合） |
| 同拍 RAW 读到旧 RAT | 数据错 | i1 源旁路 i0.new |
| freelist 只够 1 个 | 只发一半或 stall | `fl_cnt >= 2` 才双发 |
| FQ 只剩 1 条 | 出队假 2 宽 | 可变宽度（count 不足则 1 条） |
| ROB/RS 满判断用「1 条口径」 | 实际进 2 条溢出 | 用剩余 ≥2 |
| commit 仍 1 宽导致瓶颈 | IPC 不升 | 先接受；8d 后再考虑宽提交 |

## 6. 验证清单（连续 WAW / RAW 测例）

手写汇编跑 difftest + 波形，专打同拍依赖：

- 连续 WAW：`addi x5,x0,1; addi x5,x0,2; addi x5,x0,3`（FQ 出队 2+1）  
- WAW 打满：连续 8 条写 x5 → 专打 ROB 双 enq 与 old/new 链  
- 连续 RAW：`addi x5,x0,9; add x6,x5,x5; sub x7,x5,x6`（写后读）  
- 交替：`addi x5,x0,1; addi x5,x0,2; add x6,x5,x5`（i1 与 i2 同拍：RAW+WAW）  

逐项核对：
- rename：同拍两条命中同一 rd 时，`i1_rs1_phys === i0_new_phys`（旁路路径）  
- ROB：`enq1_idx = tail+1` 与 `enq0_idx` 连续；`count` 每拍 +2 时波形上 `tail` 跳 2  
- FQ：count 只剩 1 时 `deq1.valid=0` 而 `deq0.valid=1`（可变宽度生效）  
- RS：同拍两条同 rd 的 `old_phys` 正确；提交后 x5 最终值是最后一条  
- BusyTable：同拍 set2 后 `ready` 位正确；`fl_cnt` 不足时单发不 stall 全拍

`core.scala` 里对 lane 1 采取了保守策略，只让普通指令走双发射，CSR / fence.i / mret / ebreak 仍按单发思路处理，先把 2 宽的主干跑稳。

最终版要特别注意 lane 1 的两个保护：

```scala
val lane1_try = fq.io.deq1.valid && !id0_special && !id0_is_ctrl && !id1_special
val lane1_need_free = id_doren.asUInt +& id1_doren.asUInt
val lane1_free_ok = !id1_doren || (rename.io.free_cnt >= lane1_need_free)
val lane1_block = lane0_block || !lane1_try || !lane1_free_ok || !lane1_space_ok
val en_ren1 = en_ren && idu1.io.out.valid && !lane1_block
```

这里必须用 `+&`。普通 `+` 对 1 bit UInt 相加时结果仍可能只有 1 bit，`1 + 1` 会被截断成 `0`，表现为 freelist 只剩 1 个物理寄存器时仍允许两条写寄存器指令同拍发射，最后 lane1 会拿到 p0。
